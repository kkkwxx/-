## A. 已解决（照做即可）

### A-01 采集请求间歇性握手失败（约 40—60%）

- **现象**：同一个 feed 连续请求 6 轮只成功 1—4 轮；异常为 `httpx.ConnectError: [SSL: UNEXPECTED_EOF_WHILE_READING] EOF occurred in violation of protocol`。**连 news.google.com 也一样**，与具体站点无关。
- **根因**：本机出网在密集 TLS 握手时被丢弃/重置。**不是 TLS 版本问题，不是站点问题，也不是 UA 问题。**
- **试过但否掉**：
  - 强制 `maximum_version=TLSv1_2` → nasa 2/6、fnal 2/6，**无改善**
  - 单 `httpx.Client` + keep-alive 连接复用 → nasa 1/3、fnal 1/3，**仍失败**
  - 换 `urllib`（stdlib，同一 OpenSSL 3.5.9）→ 同样间歇失败，排除 httpx 自身缺陷
- **采用的办法**（必须照做）：
  1. Worker 进程内**全局共用一个** `httpx.Client(headers={"User-Agent": CRAWL_USER_AGENT}, follow_redirects=True, timeout=25, limits=httpx.Limits(max_connections=8, max_keepalive_connections=8))`，**禁止每次请求新建 Client**
  2. 所有抓取走 `tenacity.Retrying(stop=stop_after_attempt(5), wait=wait_exponential(multiplier=0.6, min=0.6, max=4), retry=retry_if_exception_type(E) | retry_if_result(bad_status), reraise=True)`
     - 可重试异常 `E` = `httpx.ConnectError`、`ConnectTimeout`、`ReadTimeout`、`RemoteProtocolError`
     - 可重试状态码 = 429 / 500 / 502 / 503 / 504
  3. 不要为这个问题加 TLS 版本配置，纯属徒增复杂度
- **实测效果**：feed 拉取 **单次 3/5 → 带重试 5/5**；正文链路最多用掉 4 次尝试。
- **回归判据**：连续跑 2 轮全源采集，`task_run` 里没有"永久失败"的源；单源 `attempts` 字段可见且多数为 1。
- **已落到**：`技术栈.md` §5.5；实测数据 §12.5

### A-02 phys.org 文章页 403

- **现象**：`https://phys.org/rss-feed/space-news/` 返回 200 且 30 条正常，但每条 `<link>` 指向的文章页返回 **403**，Trafilatura 只能抽出 57 字符。
- **根因**：站点对非浏览器请求做拦截（站点策略）。
- **试过但否掉**：
  - 换浏览器 UA → 仍 403（ATel 也一样，说明伪装 UA 无效）
  - 换 `urllib` → 偶发 200，**不稳定**，不能作为依赖
  - 引入 Crawl4AI / Playwright → 403 是策略拦截，浏览器同样会被拦；且违反"不引 Playwright"红线（见 B-04）
- **采用的办法**：正文抽取走**回退链**，写 `full_text_status` 四态：
  | 值 | 触发条件 | 正文来源 |
  |---|---|---|
  | `skipped` | RSS 自带全文（如 NASA `content:encoded` 约 23 KB/条） | RSS 全文，不抓详情页 |
  | `ok` | Trafilatura 抽出 ≥200 字 | 抽取结果 |
  | `blocked` | HTTP 403 / 401 / 451 | **RSS `summary`** |
  | `thin` | 抽出 <200 字 | RSS `summary` |
  关键点：`blocked` / `thin` **不阻断流程**，`is_event` 与事实锚点都允许只用标题 + 摘要完成，只在审核台提示"未取得全文"。
- **回归判据**：抽样 10 条真实 link，正文成功率 ≥80%（当前 8/10），且失败项全部落在 `blocked`。
- **已落到**：`技术栈.md` §5.6；实测数据 §12.4

### A-03 DashScope 默认返回带 json 围栏

- **现象**：不传 `response_format` 时，`choices[0].message.content` 是 json 代码围栏（前后三个反引号）包着的 JSON，`json.loads` 直接抛 `JSONDecodeError`。
- **试过但否掉**：`enable_thinking: false` → **不影响围栏行为**，仍带围栏。
- **采用的办法**：
  1. 所有结构化调用显式传 `response_format={"type":"json_object"}`（实测 200，返回纯 JSON）
  2. 仍保留兜底：解析前剥离首尾围栏（若正文以反引号或"反引号 + json"开头、以反引号结尾，先去包裹再 `json.loads`）
  3. 再过 Pydantic 校验；失败带错误信息重试 1 次；再失败转 `pending` 待人工
- **回归判据**：`ai_run` 里 `output_json` 解析失败率 <1%；随机抽 5 条调用确认 `content` 以 `{` 开头。
- **已落到**：`技术栈.md` §3.4、§8（`LLM_RESPONSE_FORMAT`）；实测 §12.2

### A-04 Google News channel 级 `<link>` 混入条目

- **现象**：用正则扫原始 XML 数 `<link>` 会多算 2 条——channel 自带 `<link>https://news.google.com/search?q=...</link>` 和 `<link>https://news.google.com/</link>`。
- **采用的办法**：**用 feedparser**，不要自写 XML 正则。channel link 只在 `feed.link`，正文条目的 link 在 `entries[i].link`。实测 `entries` 内混入 channel link 数 = **0**。
- **回归判据**：对 `gn_*` 系列源断言 `len(feed.entries) == task_run.stats.fetched`，且 `feed.link` 含 `/search?`。
- **已落到**：`技术栈.md` §12.3；`技术栈选型评估.md` §6.2

### A-05 Google News 原始链接回溯全失效

- **现象**：Google News RSS 的 `link` 是 `https://news.google.com/rss/articles/CBMi...`，四条回溯路径全部失效：
  1. base64 解码 → 得到的是加密后的一串，不含原始 URL
  2. `HEAD` 跟随跳转 → 停在 Google 自己的 consent 页
  3. 抓页面里的 `data-n-au` → 已不存在
  4. 调 `batchexecute` 接口 → 需要动态 token，签名校验失败
- **采用的办法**：**不回溯**。改用条目内自带的 `<source url="https://news.sciencenet.cn">科学网—新闻</source>` 直接拿媒体域名做定级（实测 44/44 条可取）。字段约定：
  - `resolved_url = null`
  - `resolve_status = 'unresolved'`
  - `publisher_name` = `<source>` 文本，`publisher_url` = `<source url>`
  - 保留原始跳转链供人工核对
- **回归判据**：`gn_*` 源落库的 `article.publisher_url` 非空比例 = 100%，且 `source_level` 由域名规则判定（不是一律 B）。
- **已落到**：`step01/03-信源管理.md`、`step01/04-采集.md`

### A-06 ScienceDaily "乱码"是假警报

- **现象**：探测结果里出现 `ESAâ€™s`，一度以为是源编码问题。
- **根因**：**探测工具造成的假象**。PowerShell 默认按 cp1252 解码；源返回 `Content-Type: application/xml` 无 charset，但**字节本身是合法 UTF-8**（严格解码成功，撇号是 U+2019）。
- **采用的办法**：
  1. 不依赖服务器声明的 charset
  2. 先按 UTF-8 **严格**解码（`errors='strict'`），成功就用
  3. 失败再嗅探（`charset-normalizer` / `lxml` 自动），并记 `decode_strategy` 字段便于排障
- **回归判据**：回归测试断言 ScienceDaily 摘要里的撇号是 **U+2019**（显示为 `'`）；出现 `â€™` 即解码用错。
- **教训（重要）**：**探测工具的解码行为会伪造结论**。凡是"源有问题"的结论，必须在真实栈（httpx + feedparser + trafilatura）上复测才能写进验收依据。
- **已落到**：`step01/05-采集数据测试.md` §3.3；`技术栈.md` §12

### A-07 Google News 连续请求 429

- **现象**：短时间内连续请求 `news.google.com/rss/search` 会返回 429 `limit_requests`。
- **采用的办法**：同源**串行**、相邻请求间隔 **≥1 秒**；源间并发上限 4（`ThreadPoolExecutor(max_workers=4)`）；429 走 A-01 的重试链（指数退避 0.6→4 s）。
- **回归判据**：全源采集一轮里 429 出现次数 ≤1，且都被重试救回（`task_run` 无失败）。
- **已落到**：`技术栈.md` §5.5

### A-08 依赖安装被网络打断

- **现象**：`uv add tenacity` 报 `client error (Connect) / tls handshake eof`；`npm install` 偶发同样失败。与 A-01 同源。
- **试过但否掉**：删掉 `.venv` / `node_modules` 整个重装 → 耗时且下一次装依赖仍会失败。
- **采用的办法**：装依赖一律包一层重试（PowerShell 示例，失败等 2—3 秒再试，最多 5 次）：

```powershell
for($i=1;$i -le 5;$i++){ uv add tenacity 2>&1 | Select-Object -Last 3; if($LASTEXITCODE -eq 0){"ok attempt $i"; break}; Start-Sleep 3 }
```

- **回归判据**：`uv run python -c "import tenacity"` 无报错。
- **备注**：**不要**为了绕这个改 pip 镜像源或关 SSL 校验——那是把网络抖动误判成证书问题。

### A-09 PowerShell 写文件破坏中文 / 加 BOM

- **现象**：`Set-Content -Encoding utf8` 写出带 BOM 的文件；对含中文的文件先 `Get-Content -Raw` 做 `-replace` 再写回，中文变 `鍚庣`，TypeScript 报 `error TS1002: Unterminated string literal`。
- **根因**：Windows PowerShell 5.1 的默认编码与 `-Encoding utf8` 都会带 BOM，且 `Get-Content` 读取编码不一致时会把 UTF-8 字节按本地代码页解释。
- **采用的办法**：
  1. **文档与源码一律用编辑工具改写**（Write / Edit），不要用 shell 做文本替换
  2. 必须用 PowerShell 写文件时，用无 BOM 写法：

```powershell
[System.IO.File]::WriteAllText($path, $text, (New-Object System.Text.UTF8Encoding($false)))
```

  3. 写前用 `[System.IO.File]::ReadAllBytes()` 检查前 3 字节是否 `EF BB BF`

- **回归判据**：`BOM=False`；中文注释在文件里正常显示；`tsc -b` / `python` 解析无报错。
- **备注**：本项目所有 `.md` 均为无 BOM UTF-8，新增文档必须保持一致。

### A-10 Edit 工具 payload 解析失败

- **现象**：`EDIT_PARSE_FAILED: PUT with a colon requires at least one + body row; use CUT to delete`。
- **根因**：`PUT >$:` 后面先写了一个空行再写 `+正文`，空行被当成空 body 行。
- **采用的办法**：`+` 开头的 body 行**必须紧跟** header 行，中间不留空行；正文里的空行写成单独的 `+`。
- **回归判据**：编辑返回 `status: modified` 且 hunk 内容与预期一致。

### A-11 行内三反引号破坏 Markdown 表格

- **现象**：表格单元格里写三个反引号（用来举例 json 围栏）会把表格提前截断，后续行渲染成代码块。
- **采用的办法**：用文字描述——"json 代码围栏（前后各三个反引号）"，**不要在正文里写字面三反引号**；行内代码里最多用单个反引号。
- **回归判据**：搜全文的三连续反引号，结果只剩合法的代码块起始/结束行（行首独占），没有出现在句子中间。

### A-12 单次写入过大会被污染

- **现象**：单次 `Write` 内容接近或超过 ~100 KB 时，出现重复填充/内容错乱（本会话早期曾出现 134 KB 重复填充）。
- **采用的办法**：单块控制在 **≤8—10 KB**；剩余部分用 `Edit` 的 `PUT >$:` 追加；追加时避免以 `---` 单独起行。
- **回归判据**：写入后 `totalLines` 与预期一致，抽查首尾段落无重复。

### A-13 pro-components 打包体积 1.8 MB

- **现象**：引入 `@ant-design/pro-components` 后，`vite build` 产出单 chunk `index.js` **1,835 kB（gzip 568 kB）**，触发 Vite 的 500 kB 警告。
- **采用的办法**（方案已定，实现阶段验证）：
  1. 路由级懒加载：`const Admin = React.lazy(() => import('./pages/admin'))`，`/admin/*` 与 `/column/*` 各自成 chunk
  2. `vite.config.ts` 里 `build.rollupOptions.output.manualChunks` 把 `antd` / `@ant-design/pro-components` / `echarts` 拆成独立 vendor chunk
  3. 栏目页（面向用户）**不要** import 任何 pro-components，只走原生 CSS + 少量 antd
- **回归判据**：`/column` 首屏主 chunk gzip ≤500 kB；`npm run build` 无 500 kB 警告（或警告仅出现在 admin chunk）。
- **状态**：⚠️ 方案已定，**尚未在真实工程里验证**

### B-04 phys.org 正文怎么办

- **选项**：
  1. **接受"仅摘要"**（当前实现方案）
  2. 继续尝试其它 UA / 降频策略拿正文 —— 有合规与稳定性风险
  3. 引入 Crawl4AI —— 违反"库级组件 ≤3"红线，需先删掉一个（Faker 可删）
- **我的建议**：**①**。`phys.org` 的 RSS `summary` 已含"谁做了什么"的关键信息，足以支撑 `is_event` 与事实锚点；审核台会标"未取得全文"，人工可点原链接核对。

### B-05 标题字数口径冲突

- **现状**：需求 §7.1 写"10—18 字"，但它自己给的示例是 8—9 字（如"科学家抓到'鬼'了？"= 9 字、"小行星贴脸地球！"= 8 字）；且**没说字数含不含标点**。
- **选项**：
  1. 硬校验 10—18 字（**需求示例会被判不合规**）
  2. 10—18 字作建议，硬校验 8—20 字（宽松，保住示例）
  3. 字数**不含标点**、按 10—18 硬校验，并把需求示例作为"已知例外"写进评测集
- **我的建议**：**③**，理由：既尊重需求的显式数字，又能让需求示例通过（示例去掉标点后是 8—10 字，仍偏短，需在评测集里标注为"参考示例、不作硬断言"）。
- **阻塞**：**这是真正阻塞开发的**——AI 加工的 prompt 约束、轻校验规则、评测集断言三处都依赖它
- **决策后归档**：写进 `06-AI 加工`（待写）与评测集；本条转 A 区并链接到该文档

### B-06 C 级源是否真接抓取

- **选项**：

  2. 用 RSSHub 公共实例拿微博/豆瓣线索（外部依赖、可能随时不可用）
  3. 自己写抓取（登录/反爬/合规风险，工期不够）
- **我的建议**：**①**。待定池的价值在**流程**而不是数据来源；手工导入 1 条"泰国灵异综艺"线索就能完整演示状态机，且 100% 可控。
- **阻塞**：待定池演示是否有真实 C 级数据
- **决策后归档**：07 审核工作台文档里写明"线索入口 = 手工导入"；本条转 A 区

### B-07 模型分工是否按成本调整

- **现状**：实测 1 token 的空请求，`qwen3.8-flash` 消耗 **110 tokens**（带思考开销），`qwen-flash` 只消耗 **10 tokens**。分类/抽取是高频调用，成本差异会被放大。
- **选项**：
  1. 按 v1.0 分工：`qwen3.8-flash` 做分类/抽取，`qwen-plus` 做生成
  2. `qwen-flash` 做分类/抽取，`qwen-plus` 做生成，`qwen3.8-flash` 只用于难例
  3. 统一 `qwen-plus`
- **我的建议**：**②**。分类/抽取任务简单、调用量大，用便宜的；生成质量敏感、调用量小，用好一点的。这样 `LLM_DAILY_TOKEN_BUDGET=200000` 能撑更久，演示时不会中途额度告警。
- **阻塞**：`.env.example` 默认值；`07-AI 加工` 的模型分工表
- **决策后归档**：更新 `技术栈.md` §3.4 与 §8；本条转 A 区
- **备注**：若你更看重"分类准确率"而不是成本，选①，我会把 flash 与 plus 的准确率在评测集上对比后回报

## E. 归档规则（等你说"归档"再动）

本篇是**活文档**，不主动清理。归档动作由你指挥，我按下列规则执行：

### E.1 状态取值（只有四种）

| 状态 | 含义 | 谁能改 |
|---|---|---|
| ✅ 已解决 | 有可照做的办法，且已落到某份文档 | 我 |
| ⏳ 待你决策 | 我给了建议但不替你拍 | 你 |
| 🔧 待收敛 | 需要真实数据才能定 | 我（到实现那步） |
| 📦 已归档 | 已解决且不再需要频繁查看 | 你说了算 |

### E.2 归档时我会做的事

1. **B 类条目**：按你的决策改写成"已解决 + 决策结论 + 决策日期"，移到 A 区；同时在相关实现文档（03/04/06/07…）落一条对应约束。
2. **A 类条目**：不删除。踩过的坑第二次踩照样浪费时间，所以正文保留；当 A 区超过 20 条时，把"纯工具类"（A-08~A-12 这种）折叠进附录，主表只留与业务相关的。
3. **C 类条目**：收敛出结论后移入 A 区，并在原处写"已收敛（日期）→ 见 A-NN"。
4. **D 类（删除记录）**：永久保留，防止有人"恢复"旧文档。
5. 每次归档更新 §F 变更记录，并在 §0.1 索引表同步状态。

### E.3 什么时候该归档

- 你完成一批决策（比如一次回我 3—5 个 B 编号）之后
- 进入新 step（如从 step01 采集进入 step02 数据模型）之前
- 交付前收口（把"待决策"清零，否则演示文档里会出现"这里还没定"）
