## 1. 系统骨架（一句话）

定时拉一批新闻 → 定级分流为「候选池 / 待定池」→ 去重合并成事件 → AI 三级加工（事实卡 → 标题摘要 → 成稿）→ 人工审核 → 发布与推送。

---

## 2. 分段与边界

| 段 | 输入 | 输出 | 关键边界 |
|---|---|---|---|
| **接入** | 源配置、手工线索 | `raw_item` | 信源管理只管配置与健康；采集只管运行与定级 |
| **定级** | `raw_item` + 出处域名 | 候选池 / 待定池 | 采集任务**末段同步执行**，不是独立后置模块 |
| **聚合** | 同事件多条候选 | `event` + 主稿 | 去重合并在聚合层，不在采集 |
| **加工** | 事件 | 事实卡 → 摘要 → 成稿 | 唯一异步链，可重跑 |
| **审核发布** | 待审稿 | 对外推送 | 人工闸门，不可绕过 |

---

## 3. 已固定的架构级决策

1. **采集只保召回，精度交下游**：漏采不可恢复，多采可过滤。
2. **信源管理与采集解耦**：`POST /api/sources/{id}/poll` 只插一条 `task_run(pending)`，两模块不互相调用。
3. **定级是三层不是一桶**：
   - **L1 源级** `source.level`（人配）→ 仅用于文章初始占位、Dashboard 分组、A 级 `expected_domains` 校验
   - **L3 域名级** `source_domain_rule`（人配）→ 域名到等级的映射表
   - **L2 文章级** `article.source_level`（**采集时按出处域名算出，不继承 L1**）→ 决定进候选池还是待定池
   - 出处域名优先级：`resolved_url` → `publisher_url`（即 `<source url>`）→ `url` 兜底；聚合源**禁止**用 link 兜底
4. **未收录域名 fail-safe 判 C**：进待定池，同时回流「未收录域名」表，运营归类后下轮生效。
5. **不用 Celery + Redis**：APScheduler + `task_run` 表，单进程常驻。
6. **健康度不做 0—100 分数**：6 态状态灯（`ok` / `degraded` / `down` / `auth_error` / `starved` / `disabled`）+ 成功率 / 平均耗时 / 条数三个数字；`starved`（连续成功但 0 条）必须与 `empty_feed` 区分。
7. **手工导入是独立入口，不是信源管理的子项**：信源管理是「管道」，手工导入是「一滴水」；产出 1 条 `raw_item`，不进取 source 表、不轮询、不计健康度。

## 5. 优先级最高的老账（架构契约层，非实现细节）

**P0 定级规则 1 冲突**：`resolved_url` 为空即判 C，而 Google News 的 `resolved_url` 恒为空 → B 级主路径断裂。

- 修法：定级输入引入「出处域名」概念，`grade_article_source` 签名增加 `publisher_url`
- 连带缺口：域名白名单只覆盖国际媒体，实测命中 `cast.org.cn` / `news.sciencenet.cn`，需按真实报文采样扩容
