## 0. 本稿约定

### 0.1 通用约定（与 [技术栈.md](../总体架构/技术栈.md) §5 一致）

| 项 | 约定 |
|---|---|
| 前缀 | `/api`，OpenAPI 在 `/docs`，机器可读 `/openapi.json` |
| 认证 | 单管理员 JWT，`HttpOnly` Cookie，所有写操作校验"已登录" |
| 分页 | 请求 `page`（默认 1）、`page_size`（默认 20，上限 100）；响应 `items` / `total` / `page` / `page_size` |
| 时间 | ISO 8601 UTC 字符串，前端按 `Asia/Shanghai` 展示 |
| 错误 | `{ "code": "...", "message": "...", "detail": {...} }` + 对应 HTTP 状态码 |
| 审计 | 所有写操作（含 toggle / poll / reset-health / recalc）写 `review_action`，记录 `before_json` / `after_json` |
| 类型生成 | 所有响应必须是明确的 Pydantic model，保证 `openapi-typescript` 能生成可用类型 |

### 0.2 状态 → UI 映射（前端不再判断枚举）

| `health_status` | 中文标签 | 颜色 | 列表排序权重 | 主操作提示 |
|---|---|---|---|---|
| `down` | 失效 | 红 `#c62828` | 1 | 换地址或停用 |
| `auth_error` | 鉴权失败 | 紫 `#5e35b1` | 2 | 配 key 后重置 |
| `degraded` | 可疑 | 橙 `#f9a825` | 3 | 观察，多为网络抖动 |
| `starved` | 空转 | 蓝灰 `#607d8b` | 4 | 评估是否还有价值 |
| `ok` | 正常 | 绿 `#2e7d32` | 5 | — |
| `disabled` | 已停用 | 灰 `#9e9e9e` | 6 | — |

> 阈值硬编码并在详情页显示：`consecutive_failures ≥ 3 → degraded`，`≥ 10 → down`，`连续 3 次成功但 0 条 → starved`。

`S` = source，`R` = domain rule，`V` = validate，`C` = recalc。编号会写进本文与后续实现注释，方便对齐。

## 1. 接口总览：19 个端点 / 5 组

> 构型：查询 5 + 配置 4 + 动作 4 + 域名规则 5 + 重算 1 = **19**。其中 `items`（S5）、`unknown`（R4）、`recalc`（C1）、`validate-one`（V2）四个是决策的直接产物，砍不掉；域名规则拆成 5 个方法是 CRUD 的自然拆分，不是增加能力。

## 3. 端点明细

### 3.1 查询

#### S1 `GET /api/sources`

查询参数：`page`、`page_size`、`type`、`level`、`health_status`（可多值）、`enabled`、`keyword`（匹配 code / name）、`validated`（`never` / `yes`）、`sort_by`、`sort_order`

响应：`{ items: SourceListItem[], total, page, page_size }`

**默认排序（替代健康分）**，三级排序、完全可解释：

1. 状态严重度：`down` → `auth_error` → `degraded` → `starved` → `ok` → `disabled`
2. 同状态：`consecutive_failures` 降序
3. 再同：`last_success_at` 升序（最久没成功的在前）

> `sort_by` 只允许 `code` / `level` / `last_success_at` / `success_rate_7d` / `items_7d`，其余回落默认排序——避免前端传任意列名进入 SQL 拼接面。

#### S2 `GET /api/sources/summary`

响应字段：`total`、`enabled`、`by_status`（6 态计数）、`needs_attention`、`items_today`、`last_run_at`、`unknown_domain_count`、`recalc_running`

> `needs_attention` = `down` + `auth_error` + `degraded` + `starved`，前端直接当红点徽标用，不在前端重算。

#### S3 `GET /api/sources/{id}` → `SourceDetail`

#### S4 `GET /api/sources/{id}/runs`

参数：`limit`（默认 20，上限 100）、`status`（可选）
响应：`{ items: RunItem[] }`（只取最近 N 条，不翻页）

#### S5 `GET /api/sources/{id}/items`

参数：`limit`（默认 5，上限 20）
响应：`{ items: CollectedItem[] }`

### 3.2 配置

#### S6 `POST /api/sources`

请求体：`code`、`name`、`type`、`url` 或 `query_template`（按 type）、`poll_interval_min`（默认 30）、`level`（默认 B）、`enabled`（默认 true）、`expected_domains`、`title_suffix_rules`、`extra_headers`、`api_key_env`、`note`

响应 `201`：字段 `source`（`SourceDetail`）+ 可选字段 `warning`：

- `warning.code = "NOT_VALIDATED"`
- `warning.message = "该源尚未验证过，可能不可用。建议先点探活确认。"`

**关键行为（决策 0-1 的落地）**：探活**不是前置条件**。无论验证与否都返回 201，未验证则带 `warning`；此时 `last_validated_at` 保持 `null`，列表显示"从未验证"标签。

#### S7 `PATCH /api/sources/{id}`

- 只接受 14 个人工可写字段（§2.2 标"人"的）
- 传运行态字段 → `400 READONLY_FIELD`，`detail.rejected_fields` 列出字段名。**不做静默忽略**，否则前端以为改成功了
- A 级源 `expected_domains` 为空 → `400 MISSING_EXPECTED_DOMAINS`
- `code` 技术上可改，但**建议前端设为编辑态只读**：改 `code` 不会回填历史 `raw_item` 与审计记录

#### S8 `POST /api/sources/{id}/toggle`

请求 `{ "enabled": false }` → 响应 `{ "id": 3, "enabled": false, "health_status": "disabled" }`

**关键行为**：

- 停用时 `health_status` 置 `disabled`，但**保留 `consecutive_failures` 原值**
- 重新启用时**不直接置 `ok`，而是置 `degraded`（待观察）**，等首次任务成功再转 `ok`。理由：停用期间源可能已经坏了，直接绿灯会误导

#### S9 `DELETE /api/sources/{id}`

- 有 `raw_item` → `409 SOURCE_HAS_DATA`，`detail.raw_item_count` + 建议"请改用停用"
- 无数据 → `204`
- `code='manual'` 内置源 → `409 BUILTIN_SOURCE`（不可删）

### 3.3 动作

#### S10 `POST /api/sources/{id}/poll`

响应 `201`：`{ "task_run_id": 981, "status": "pending" }`

**关键行为**：只插 `task_run(task_type='poll', status='pending')`，**API 进程绝不发 HTTP 请求**。前端拿 `task_run_id` 轮询 S4 看结果。

#### S11 `POST /api/sources/{id}/reset-health`

响应：`{ "id": 3, "health_status": "ok", "consecutive_failures": 0 }`

**关键行为**：清 `consecutive_failures` 与 `last_error*`，但**保留 `success_count` / `error_count`**（累计值不清，否则成功率历史被抹掉）。写审计。

#### V1 `POST /api/sources/validate`（全量探活）

响应 `200`：`validated_at`、`total`、`ok`、`results`（`ValidateResult[]`）

**关键行为——同步接口，必须短超时，不能复用采集的重试链**：

| 参数 | 采集模式 | 探活模式 | 理由 |
|---|---|---|---|
| 超时 | 25 s | **8 s** | 探活要"能不能通"，不是"一定拿到" |
| 重试 | 5 次退避 | **1 次** | 20 源 × 5 次 × 8 s 最坏 800 s，人不可能等 |
| 并发 | 4 | 4 | 最坏约 `20/4 × 8 = 40 s` |
| 副作用 | 写 `raw_item` | **不写业务数据**，只写 `last_validated_at` | 探活是只读检查 |

> 若实测 40 s 仍太长，再改异步 + 轮询；本稿先按同步做，少一个端点。

#### V2 `POST /api/sources/validate-one`

请求体收**配置而非 id**，因为有"新建时还没保存"的场景：字段 `type`、`url` 或 `query_template`、可选 `source_id`

响应 `200`：`ValidateResult`（含 `preview` 前 3 条）

**关键行为**：不写库；仅当传了 `source_id` 时才更新该源的 `last_validated_at`。

### 3.4 域名规则

#### R1 `GET /api/source-domain-rules`

参数：`page`、`page_size`、`level`、`enabled`、`keyword`
响应：`{ items: DomainRule[], total, page, page_size }`，默认 `level` 升序 + `hit_count_30d` 降序

#### R2 `POST /api/source-domain-rules`

请求：`{ "domain": "sciencenet.cn", "level": "B", "note": "科学网，实测 GN 高频命中" }`

**关键行为（决策 1 的"一键归类"）**：

1. 域名归一（eTLD+1、小写）
2. 同域名已存在 → `409 DOMAIN_EXISTS`
3. 建规则，并**在同一事务里删除 `unknown_domain` 中该域名记录**
4. 返回 `201` + `DomainRule` + `recalc_suggested: true`

#### R3 `PATCH /api/source-domain-rules/{id}`

改 `level` / `note` / `enabled`；**改 `level` 时返回 `recalc_suggested: true`**。

#### R4 `GET /api/source-domain-rules/unknown`

参数：`page`、`page_size`、`min_hits`（默认 1）、`sort`（默认 `hit_count` 降序）
响应：`{ items: UnknownDomain[], total, page, page_size }`

**数据来源**：采集侧定级时若出处域名不在规则表 → upsert（`hit_count + 1`、更新 `last_seen_at` 与 `sample_*`）。写入在 04-采集，本模块只读 + 归类。

#### R5 `DELETE /api/source-domain-rules/{id}` → 软删除，`204`

### 3.5 重算

#### C1 `POST /api/sources/recalc-levels`

请求：`{ "scope": "all" }` 或 `{ "scope": "range", "date_from": "...", "date_to": "..." }`
响应 `202`：`{ "task_run_id": 982, "status": "pending" }`

**为什么必须有**：`article.source_level` 是**落库值**。改域名规则后历史文章等级不会自动变，不重算就会出现"同一域名昨天入库是 C、今天是 A"，审核台自相矛盾。

| 项 | 约定 |
|---|---|
| 并发 | 同时只允许 1 个重算任务，已有在跑 → `409 RECALC_IN_PROGRESS` |
| 范围 | 默认只重算**未发布**文章；`published` / `unpublished` 不追溯，避免改已上线内容 |
| 统计 | `task_run.stats_json` 记 `scanned` / `changed` / `skipped_published` |
| 版本 | 用**当前**规则表，不做规则版本化（MVP） |

### 3.6 错误码表

| `code` | HTTP | 场景 |
|---|---|---|
| `SOURCE_NOT_FOUND` | 404 | id 不存在 |
| `SOURCE_CODE_DUPLICATE` | 409 | `code` 已存在 |
| `SOURCE_HAS_DATA` | 409 | 删除时仍有 `raw_item` |
| `BUILTIN_SOURCE` | 409 | 试图删 `code='manual'` |
| `READONLY_FIELD` | 400 | PATCH 传了运行态字段 |
| `MISSING_EXPECTED_DOMAINS` | 400 | A 级源缺 `expected_domains` |
| `INVALID_TYPE_FIELD` | 400 | `rss` 却传了 `query_template` |
| `DOMAIN_EXISTS` | 409 | 域名规则重复 |
| `INVALID_DOMAIN` | 400 | 归一后不是合法 eTLD+1 |
| `RECALC_IN_PROGRESS` | 409 | 已有重算在跑 |

> 探活"源不可用"不算错误：接口照常 `200`，结果放在 `results[].ok=false`。

## 6. 本稿需要你确认的点

下面 6 个是我写的过程中做的取舍，都给了默认值。**不同意就指出编号**；同意可以完全不回，我按默认往下写。

| 编号 | 取舍 | 我的默认 | 备选 |
|---|---|---|---|
| Q1 | 全量探活同步还是异步 | 同步 + 短超时（8 s / 1 次尝试 / 并发 4，最坏约 40 s），少一个端点 | 异步 + 轮询进度 |
| Q2 | 重新启用后的初始状态 | `degraded` 待观察 | 直接 `ok` |
| Q3 | 重算是否追溯已发布文章 | 不追溯，已发布跳过 | 全覆盖追溯 |
| Q4 | M1 是否给"一键停用异常源" | 不给，只导出 CSV | 给，带二次确认 |
| Q5 | `code` 是否允许编辑 | 前端设为只读，仅新建时填 | 允许改 |
| Q6 | 列表默认列数 | 默认 11 列，其余进列设置 | 全显示（横向滚动） |

另外两处我按"必须有"直接写进去了，你觉得超范围可以砍：

| 项 | 为什么我坚持 |
|---|---|
| S5 采回条目接口 | 这是 S6「搜索内容无关」唯一能看见的手段——`starved` 抓不到它，因为那个源有条目（10 条地震新闻） |
| C1 重算等级 | `article.source_level` 是落库值，改规则不重算会导致同一域名新旧数据等级不一致 |
