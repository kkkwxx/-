## 0. 文档目的

本文固定神秘新闻 MVP 的技术选型、版本基线、运行环境和明确不引入的技术。后续代码、依赖、脚本、部署都以本文为准。

四条原则：

1. **够用**：单机、单管理员、演示规模，不为了"看起来架构完整"引入中间件。
2. **可跑**：Windows 上能一键启动；Docker 只跑依赖；换一台机器能复现。
3. **可替换**：采集、AI、存储都通过薄封装隔离，后续换模型或换库不大改业务代码。
4. **复用优先**：能直接复用成熟开源项目已有的完整能力，就不自己重写；只自己写业务差异化部分。

### 0.1 复用梯度与红线

第 4 条原则必须落成可执行的判据，否则"复用"会变成"堆项目"。复用形态按成本从低到高排序，**同等能力取更左的形态**：

| 形态 | 成本 | 例子 |
|---|---|---|
| **① 库级复用**（`pip` / `npm` 装进来） | 无运维面，随进程起停 | feedparser、Trafilatura、rapidfuzz、ProTable |
| **② 内嵌进程**（同仓库、同镜像内的模块） | 一份启动脚本 | APScheduler 调度、`task_run` 任务表 |
| **③ 独立常驻服务**（另一个端口 / 容器 / 仓库） | 启动脚本 + 健康检查 + 失败面 + 录制翻车点 | RSSHub、Firecrawl、Celery+Redis |

**本轮红线**（v2.0 据此拍板，一周工期不可突破）：

- 新增**库级组件 ≤ 3 个**（已用满：`@ant-design/pro-components`、`openapi-typescript`、`Faker`）
- 新增**常驻服务 = 0 个**
- 新增**基础设施 = 0 个**（唯一例外 `pgvector/pgvector:pg16`，它与 `postgres:16` 同一 major，只是换镜像 tag）

### 0.2 复用边界：什么必须自己写

| 尽量复用（成熟项目已有） | 必须自己设计（业务差异化） |
|---|---|
| RSS 订阅与解析（feedparser） | 信源 A/B/C 分级与域名定级规则 |
| 网页抓取与正文提取（httpx / Trafilatura） | 四类内容判定与 `is_event` 标准 |
| 定时调度（APScheduler） | 跨来源事件去重策略（实体+动作+时间） |
| 模型 API 调用（openai SDK） | 事实锚点提取与标题/导语生成策略 |
| UI 基础组件与表格表单（AntD 5 / Pro Components） | 审核状态流转与待定池补证流程 |
| 数据库与 ORM（PostgreSQL / SQLAlchemy / Alembic） | 业务数据模型（`article` / `event_cluster` / `published_article`） |
| 模糊匹配与去重原语（rapidfuzz） | 标题 10—18 字与风险 flag 的判定口径 |

## 1. 一句话总览

Windows 本地运行；Docker 只跑 PostgreSQL 16（`pgvector/pgvector:pg16` 镜像）；后端 FastAPI + SQLAlchemy 2 + Alembic + APScheduler；前端 React 18 + TypeScript + Vite + Ant Design 5 + Pro Components；前后端类型用 `openapi-typescript` 从 `/openapi.json` 自动生成；AI 用阿里百炼 OpenAI 兼容接口；单管理员、全人工审核、发布快照 + 栏目展示。

**v2.0 相对 v1.0 只加了 3 个库 + 1 个镜像 tag，没有增加任何常驻服务。**

> **镜像说明**：`pgvector/pgvector:pg16` 与 `postgres:16-alpine` 是同一个 PostgreSQL 16 major，只多带了 `vector` 扩展。MVP **不启用**向量类型，选用它是为了后续做语义去重时不用换库、不用迁移。拉取失败可无条件回退 `postgres:16-alpine`，因为 MVP 需要的 `pg_trgm` 是 PG 官方 contrib，两个镜像都有。

> **注意**：本机 `python` 指向 Anaconda base 的 3.8.5，但 uv 已经管理了 Python 3.12.16。项目统一用 uv 创建虚拟环境，不依赖 conda 环境：

```powershell
cd backend
uv venv --python 3.12
uv sync
uv run python --version
```

后续所有后端命令都用 `uv run ...`，例如 `uv run uvicorn app.main:app --reload`。`py -0p` 看不到 uv 管理的 Python 是正常的，用 `uv python find 3.12` 确认。

**为什么加 Pro Components**：一周工期里前端真正的大头是"审核工作台 + 信源管理 + Dashboard"，三者本质都是"带搜索的表格 + 详情面板 + 编辑表单"。`ProTable` 一份列配置就同时得到搜索区、分页、排序、批量操作、列显隐；`ProDescriptions` 直接做"原文对照"面板；`ProForm` 的 `rules` 直接承载标题 10—18 字这类校验。手写等价逻辑要 150 行以上 AntD `Table` 胶水代码，且演示时容易缺状态。三者与 AntD 5 同生态（Pro Components 的 peer 就是 antd 5）。

**为什么加 openapi-typescript**：后端 Pydantic 模型一改，前端手抄的 TS interface 就悄悄过期，是演示当天最典型的翻车源。`npx openapi-typescript http://localhost:8000/openapi.json -o src/api/schema.d.ts` 把这条链一次焊死：后端改字段 → 前端 `tsc` 立刻报错。

不引入：Redux、Zustand、Next.js、Tailwind、额外 UI 框架、refine.dev。服务端状态交给 TanStack Query，登录态用 React Context，栏目页用原生 CSS。`refine` 这类 CRUD 抽象框架对"待定池 → 补充证据 → 复核 → 发布"的自定义流转帮不上忙，反而要按它的资源模型改造业务，净成本为正。

| 不引入 | 原因 | 替代 |
|---|---|---|
| Scrapy | 我们的采集是同构 RSS/API 拉取，不是异构站点爬取；Scrapy 自带调度器 + 去重器会与 APScheduler + `task_run` 状态机打架，形成两套任务真相 | httpx + feedparser + APScheduler |

| Miniflux | 定位是多用户 RSS 阅读器（自动更新、全文获取、全文搜索、OPML），我们要的是"抓 → 落库 → 判事件"，feedparser 40 行即可；引入代价是 Go 服务 + 独立数据库 | feedparser |
| LiteLLM | 只有一个 OpenAI 兼容端点，多一层网关无收益；换供应商只需改 `base_url` 与 model 名 | openai SDK + 薄封装 |
| 向量数据库（Milvus/Qdrant/Chroma） | 一周工期成本失衡；标题指纹 + 实体/事件匹配已覆盖 MVP 去重 | `pg_trgm` + rapidfuzz + 规则 |
| sentence-transformers / torch | 模型下载与 GPU 依赖，权重远大于收益 | 同上 |

> **同步还是异步**：MVP 用同步 SQLAlchemy + psycopg 3，FastAPI 同步路由跑在线程池；采集用 `ThreadPoolExecutor` 限制并发（建议 4）。理由是当前规模（10—20 个源、单 Worker、演示优先）下，同步代码更短、更好排障；AI 和抓取都是 I/O，线程池足够。后续真要提吞吐，再按模块换 async，不影响表结构。

### 3.4 AI

| 项 | 选择 | 说明 |
|---|---|---|
| 平台 | 阿里云百炼 DashScope | OpenAI 兼容接口 |
| Base URL | `https://dashscope.aliyuncs.com/compatible-mode/v1` | 已实测（含 `/models`，返回 191 个模型） |
| SDK | `openai` Python SDK | 不直接用 HTTP 拼 |
| 分类 / 抽取 | `qwen3.8-flash` + `enable_thinking:false` | **已核实存在**：200，回显 `qwen3.8-flash` |
| 标题 / 导语 / 摘要 | `qwen-plus` | 200，回显 `qwen-plus` |
| 难例复核 | `qwen3.8-max` | **已核实存在**：200，回显 `qwen3.8-max`；可选，按需 |
| 不使用 | `qwen3-max`（404，不存在）、`qwen-turbo`（429 `limit_requests`） | 实测结果 |
| 输出格式 | `response_format={"type":"json_object"}` + Pydantic 校验 | 实测 `json_object` 与 `json_schema` 均返回 200；失败修复一次，再失败转待定 |
| 可选替代 | `instructor`（结构化输出 + 自动重试） | 后置；Pydantic 手写校验够用 |

不引入：LangChain、LlamaIndex、本地大模型、向量数据库、embedding 语义去重（初期）。

> **实测注意（必须遵守）**：不带 `response_format` 的默认文本模式，返回内容会被 json 代码围栏（三个反引号 + json）包裹，实测 `content` 里带前后围栏、不是纯 JSON。因此**所有结构化调用必须显式传 `response_format={"type":"json_object"}`**，并在解析前仍做一次围栏剥离作为兜底。

## 5. 关键约定

### 5.1 接口

- 统一前缀 `/api`；OpenAPI 在 `/docs`，机器可读在 `/openapi.json`。
- JSON 请求/响应；时间字段 ISO 8601 UTC，前端按 `Asia/Shanghai` 展示。
- 分页参数 `page`、`page_size`；列表返回 `items`、`total`、`page`、`page_size`。
- 错误格式：`{ "code": "...", "message": "...", "detail": ... }`。

### 5.2 认证

- 单管理员；bcrypt 存密码哈希，不存明文。
- 登录成功签发 JWT，放在 `HttpOnly` Cookie，`SameSite=Lax`；前端 Axios 带 `withCredentials`。
- 接口：`POST /api/auth/login`、`POST /api/auth/logout`、`GET /api/auth/me`。
- 不做多角色 RBAC；所有管理接口只校验"已登录"。

### 5.3 数据

- 数据库存 UTC；`APP_TIMEZONE` 只影响展示和时效判断。
- 原始 HTML 默认存 `raw_item.raw_html`（TEXT）；超过 `RAW_HTML_MAX_DB_BYTES` 落本地 `storage/raw/`，库里存路径。
- 审计 payload 用 JSONB；正文用 TEXT。
- 所有状态变更走事务；发布快照 `published_article.article_id` 唯一。
- 迁移时执行 `CREATE EXTENSION IF NOT EXISTS pg_trgm;`，并给 `article.title` 建 `gin_trgm_ops` 索引。

### 5.4 前端

- `/admin` 用 Ant Design + Pro Components；`/column` 用原生 CSS，移动端优先，最大宽度 480px。
- 开发时 Vite `server.proxy` 把 `/api` 代理到 `http://localhost:8000`，减少 CORS。
- 后端同时配置 CORS 白名单 `http://localhost:5173`，方便直接调 API。
- 不在 MVP 引入 Nginx；`start.ps1` 负责按顺序起依赖、迁移、seed、API、Worker、前端。
- **类型生成**：`npm run gen:api` = `openapi-typescript http://localhost:8000/openapi.json -o src/api/schema.d.ts`；后端 schema 变更后必须重跑并提交 `schema.d.ts`。
- **路由级懒加载**：`React.lazy` + `Suspense` 拆分 `/admin/*` 与 `/column/*`。实测引入 Pro Components 后单 chunk 达 1.8 MB（gzip 568 KB），必须靠分包把首屏压回去。

### 5.5 采集 HTTP 规范（v2.0 实测新增）

这一节是 v2.0 最重要的工程约束，来自 §12 的实测。

1. **连接必须复用**：整个 Worker 进程共用一个 `httpx.Client`（`max_connections=8`、`max_keepalive_connections=8`），**禁止每次请求新建 `Client`**。
2. **必须带 tenacity 退避重试**：可重试异常 = `httpx.ConnectError`、`ConnectTimeout`、`ReadTimeout`、`RemoteProtocolError`，可重试状态码 = 429 / 500 / 502 / 503 / 504。参数建议 `stop_after_attempt(5)` + `wait_exponential(multiplier=0.6, min=0.6, max=4)`。
3. **不做 TLS 版本特殊处理**：实测强制 `max_version=TLSv1_2` 并不能改善失败率，问题不在 TLS 版本，加这层配置只是徒增复杂度。
4. **单源串行、源间并发 4，且同 host 互斥**：`ThreadPoolExecutor(max_workers=4)`；同 host 用互斥锁保证串行，最小间隔 1 秒（Google News 2 秒，因为它 6 个源共用一个 host，实测连续请求会 429）。锁必须包住"等待 + 请求"整体，不能只包 sleep。
5. **抓取标识**：统一 `CRAWL_USER_AGENT`，不要伪装成浏览器 UA 去绕 403（ATel 实测浏览器 UA 也 403，属于需要 token 的接口）。

### 5.6 正文抽取回退链（v2.0 实测新增）

正文不是"必须抽到"，而是"抽不到也要能继续走流程"。顺序如下：

1. 先判断 RSS 是否自带全文：NASA 的 `content:encoded` 单条约 23 KB，**直接用，不再抓详情页**。
2. 否则 `httpx` 抓详情页 → `trafilatura.extract(..., favor_precision=True, include_comments=False)`。
3. 403 / 空结果 / 正文 < 200 字 → 回退 `raw_summary`（RSS 摘要），并写 `full_text_status`：
   - `ok`：抽到正文
   - `blocked`：站点拒绝（实测 `phys.org` 文章页对非浏览器请求返回 403）
   - `thin`：抽到的正文过短
   - `skipped`：RSS 自带全文
4. `blocked` / `thin` 不阻断后续流程——`is_event`、事实锚点都可以只用标题 + 摘要完成，只是审核台要提示"未取得全文"。

## 12. 本轮实测记录（2026-11-26）

本节是 v2.0 选型的事实依据，也是"待核实清单"的关闭记录。所有实测在本机完成：Windows PowerShell 5.1、Python 3.12.16（uv）、Node 24.15.0、Docker 29.5.3、无 HTTP 代理。

### 12.1 百炼模型 ID 探活（关闭待核实 #1）

方法：`POST /chat/completions`，`messages=[{"role":"user","content":"ping"}]`，`max_tokens=1`，记录 HTTP 状态与响应里的 `model` 回显。

| 请求 model | HTTP | 回显 `model` | total_tokens | 结论 |
|---|---|---|---|---|
| `qwen3.8-flash` | 200 | `qwen3.8-flash` | 110 | **可用**（含思考开销） |
| `qwen3.8-max` | 200 | `qwen3.8-max` | 81 | **可用** |
| `qwen-flash` | 200 | `qwen-flash` | 10 | 可用（备选） |
| `qwen-max` | 200 | `qwen-max` | 10 | 可用（备选） |
| `qwen-plus` | 200 | `qwen-plus` | 10 | 可用 |
| `qwen3-max` | **404** | — | — | 不存在，不要写进配置 |
| `qwen-turbo` | **429** | — | — | `limit_requests`，与 v1.0 记录一致 |

`GET /models` 返回 191 个模型，列表中出现 `qwen3.8-flash`、`qwen3.8-max`、`qwen3.8-max-0902`，**确认 v1.0 的模型名写法正确，不需要改名**。

### 12.2 `response_format` 支持度（关闭待核实 #2）

模型固定 `qwen-plus`，`max_tokens=50`，请求"返回 JSON: {"ok":true}"。

| `response_format` | HTTP | 返回 `content` | 结论 |
|---|---|---|---|
| `{"type":"json_object"}` | 200 | `{"ok":true}` | **推荐** |
| `{"type":"json_schema", ...}` | 200 | `{"ok":true}` | 被接受，可作备选 |
| `{"type":"text"}`（默认） | 200 | 带 json 代码围栏（前后三个反引号） | **不是纯 JSON** |
| 不传 + `enable_thinking:false` | 200 | 带 json 代码围栏（前后三个反引号） | 同上 |

结论：`enable_thinking:false` 不影响围栏行为；**结构化调用必须显式传 `json_object`**，并保留围栏剥离兜底。

### 12.3 feedparser 与 Google News 报文（关闭待核实 #6）

| feed | HTTP | entries | bytes | bozo |
|---|---|---|---|---|
| `nasa_breaking` | 200 | 10 | 229,679 | 0 |
| `fnal_news` | 200 | 10 | 68,417 | 0 |
| `phys_space` | 200 | 30 | 31,748 | 0 |
| `sd_astronomy` | 200 | 60 | 45,639 | 0 |
| `watchers` | 200 | 10 | 13,964 | 0 |

`gn_particle`（`q=中微子`）：HTTP 200、**44 条**、47,150 字节、`bozo=0`。

- **`<source url>` 全部可取**：44/44 条带 `entry.source.href`。样例：`title=一文读懂2026诺贝尔物理学奖…` / `source.href=https://www.cast.org.cn` / `source.name=中国科学技术协会`。
- **channel 级 `<link>` 不会混入 `entries`**：实测 `entries` 内混入数 = **0**，channel link 只出现在 `feed.link`（`https://news.google.com/search?q=中微子&...`）。v1.0 记录的"按 `<link>` 全局正则会多算 2 条"是**用正则扫原始 XML**造成的，**用 feedparser 不会踩到**——这是选择 feedparser 而非自写 XML 解析的直接收益。
- `published_parsed` 可直接得到时间元组，`published` 原文为 `GMT` / `EST` / `+0000` 三种，交给 `python-dateutil` 兜底即可。

### 12.5 网络抖动与重试（待核实清单外的新发现，已写入 §5.5）

失败全部是 `ConnectError: [SSL: UNEXPECTED_EOF_WHILE_READING]`（握手期被对端关闭）。**强制 TLS 1.2 不能稳定改善**，说明不是 TLS 版本问题，而是本机出网在密集握手时被丢弃。连接复用（单 Client + keep-alive）也无法根除（nasa 1/3、fnal 1/3）。

| feed | 单次结果 | 带重试结果 | 实际尝试次数 |
