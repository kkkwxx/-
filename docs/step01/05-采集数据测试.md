## 0. 本文怎么用

这份文档不是"必须全过"的验收清单，而是三样东西：

1. **实测基线**：每个源现在真实返回什么（状态码、条数、时区、字段）。
2. **期望输出**：解析后应该变成什么形状（`RawItemDraft`、接口返回 JSON）。
3. **边界条件清单**：所有容易踩的坑，宽的写，宁多勿少。

收敛方式：文中标 `【实测】` 的是已经跑出来的事实，标 `【待测】` 的是推断待验证。代码完成后，把 `【待测】` 逐条跑成 `【实测】`，并把区间收窄为具体值。

## 1. 实测环境与复现

| 项 | 值 |
|---|---|
| 时间 | 2026-11-25 |
| 系统 | Windows，PowerShell 5.1 |
| 网络 | 直连，未配置 `HTTP_PROXY` / `HTTPS_PROXY` |
| UA | `MysteryNewsDemo/1.0 (+mailto:demo@example.com)` |
| 方法 | 每个 URL 单次 GET，25s 超时，保存原始报文 |

**重要前提**：本次实测**没有走代理**，且 `news.google.com` 和多数境外源可直连。这与"国内需要代理"的预期不同，说明当前网络环境不是典型境内环境。**换到演示机后必须重测**，这份基线可能整体不成立。

复现命令（PowerShell）：

```powershell
$UA = "MysteryNewsDemo/1.0 (+mailto:demo@example.com)"
Invoke-WebRequest -Uri $url -Headers @{'User-Agent'=$UA} -TimeoutSec 25 -UseBasicParsing
```

建议后续用 `scripts/probe_sources.ps1` 固化这个探测，输出与本文 §2 同结构的表。

### 1.1 探测方法不等于最终采集方法

本次探测**没有用设计里的技术栈**，两者的差异必须清楚，否则会把探测结论当成实现结论：

| 维度 | 本次探测 | 设计规定（04-采集） | 差异的影响 |
|---|---|---|---|
| HTTP 客户端 | PowerShell `Invoke-WebRequest` | `httpx.Client` | 超时、重试、代理、HTTP2 行为不同 |
| 解析 | 正则数 `<item>`、抽字段 | `feedparser` | 正则会把 channel 级 `<link>` 算进去（已实测踩到），feedparser 不会 |
| 编码 | PowerShell 默认 cp1252 | 按 charset，否则显式 UTF-8 | **本次出现的 `ESAâ€™s` 乱码是工具造成的，见 §3.3** |
| 条件请求 | 无 | `If-None-Match` / `If-Modified-Since` | 304 行为未验证 |
| 重试 | 无 | `tenacity` 3 次退避 | 5xx / 429 的真实重试行为未验证 |
| 并发 | 串行 | `ThreadPoolExecutor(4)` | 429 阈值可能不同 |
| 代理 | 未配置 | 支持 `HTTP_PROXY` | 境内环境结论可能整体不成立 |

**因此本文结论分两类：**

- **可信（与客户端无关）**：源是否存活、报文里有哪些字段、时区怎么写、条目量级、内容是否切题。
- **需在真实栈上复核（依赖客户端）**：编码处理、304、429、并发限速、超时阈值。

## 3. 真实报文结构（决定解析器怎么写）

RSS 看着都是 RSS，实际字段差异很大。下面四类是本项目会遇到的真实形态。

### 3.1 类型 A：NASA / Fermilab 型（WordPress）

```xml
<item>
  <title>APOD: 2026 November 25 – SPHEREx Seeing Through Dust</title>
  <link>https://science.nasa.gov/image-article/apod-2026-november-25-...</link>
  <dc:creator><![CDATA[]]></dc:creator>
  <pubDate>Wed, 25 Nov 2026 05:05:00 +0000</pubDate>
  <category><![CDATA[APOD]]></category>
  <guid isPermaLink="false">https://science.nasa.gov/image-article/apod-...</guid>
  <description><![CDATA[APOD Science APOD ... [&#8230;]]]></description>
  <content:encoded><![CDATA[<div class="hds-module ...">大段 HTML</div>]]></content:encoded>
</item>
```

要点：

- `dc:creator` **可能为空 CDATA**，`<![CDATA[]]>` 要能安全解析成空串而不是报错。
- `pubDate` 用 `+0000`。
- `description` 是 CDATA 纯文本，但**结尾带 `[&#8230;]` 截断标记**，需要清掉。
- `content:encoded` 是全文 HTML，**体积约占整个报文的 95%**（NASA 226 KB / 10 条）。
- `guid` 与 `link` 相同，但 `isPermaLink="false"` —— **不能因为 `isPermaLink="false"` 就认为 guid 不可用**。

### 3.2 类型 B：phys.org 型（guid 不是 URL）

```xml
<item>
  <title>South Pole Telescope releases clearest map ever of matter...</title>
  <description>The earliest light in the universe...</description>
  <link>https://phys.org/news/2026-11-south-pole-telescope-clearest-distant.html</link>
  <category>Astronomy</category>
  <pubDate>Wed, 25 Nov 2026 10:00:01 EST</pubDate>
  <guid isPermaLink="false">news714821461</guid>
  <media:thumbnail url="https://scx1.b-cdn.net/csz/news/tmb/2026/..." width="90" height="90" />
</item>
```

要点：

- **`guid` 是 `news714821461` 这种内部 ID，不是 URL。** 任何"用 guid 当 url"的实现都会在这里崩掉。**URL 必须取 `<link>`，不能取 `<guid>`。**
- `pubDate` 用 `EST` 而不是 `-0500`。`EST` 是固定 UTC−5，**不随夏令时切换**；`dateutil` 会按字面解析成 UTC−5，与真实 EDT（UTC−4）差 1 小时。
- `description` 是纯文本、无 CDATA、无 HTML 标签，长度约 360 字符。

### 3.3 类型 C：ScienceDaily 型（不带 charset）

```xml
<item>
  <title>A space telescope hunting for dark matter just discovered something unexpected</title>
  <link>https://www.sciencedaily.com/releases/2026/11/261124055852.htm</link>
  <description>ESA’s Euclid space telescope has discovered its first previously unknown comet...</description>
  <pubDate>Wed, 25 Nov 2026 05:35:04 EST</pubDate>
  <guid isPermaLink="true">https://www.sciencedaily.com/releases/2026/11/261124055852.htm</guid>
</item>
```

要点：

- **HTTP `Content-Type` 只给 `application/xml`，不带 charset。** 这是源的真实行为，已复测确认。
- **但源的内容是好的**：原始字节按严格 UTF-8 解码完全成功，撇号是正常 U+2019。早先记录的 `ESAâ€™s` 是探测工具（PowerShell 默认按 cp1252 解）造成的，**不是源的问题**。
- 结论：不要依赖服务器声明编码，**显式按 UTF-8 解**，失败再嗅探。这件事不难，但漏了会静默出错。
- 60 条/次、45 KB，是本项目除 NASA 外最大的包。
- `guid isPermaLink="true"` 且等于 URL，这类可以直接用 guid。

### 3.4 类型 D：Google News 型（字段最特殊）

```xml
<item>
  <title>地球引力临时捕获一颗"迷你月球" - 科学网—新闻</title>
  <link>https://news.google.com/rss/articles/CBMiZkFVX3lxTFBwa2Z...</link>
  <guid isPermaLink="false">CBMiZkFVX3lxTFBwa2Z...</guid>
  <pubDate>Wed, 25 Nov 2026 07:00:34 GMT</pubDate>
  <description>&lt;a href="https://news.google.com/rss/articles/..."&gt;地球引力临时捕获一颗"迷你月球"&lt;/a&gt;&amp;nbsp;&amp;nbsp;&lt;font color="#6f6f6f"&gt;科学网—新闻&lt;/font&gt;</description>
  <source url="https://news.sciencenet.cn">科学网—新闻</source>
</item>
```

要点，每一条都影响实现：

1. **`<source url="...">` 直接给出媒体域名**，实测 16/16 条都有。这意味着**定级不需要等链接回溯**，可以直接用这个域名定 A/B/C。这是本次实测最有价值的发现。
2. **`<title>` 末尾带 ` - 媒体名`**，实测 16/16 条都是这个格式，必须剥离才是干净标题。
3. **`<description>` 是转义过的 HTML**（`&lt;a href=...`），里面还重复了一次跳转链接和媒体名。清洗时别把它当正文。
4. `pubDate` 用 `GMT`。
5. **feed 里除了 item 的 link，还有 channel 级 link**（`https://news.google.com/search?...` 和 `https://news.google.com/`）。实测一个 18 条 link 的里有 2 条是 channel 级的，**按 `<link>` 全局正则抓会多算 2 条**。

### 3.5 链接回溯：实测不可行【重要修正】

04-采集 §8.1 写的三级策略，实测结果如下：

| 策略 | 实测结果 | 结论 |
|---|---|---|
| ① base64 本地解码出原始 URL | 解码成功，但内容是新格式 ID（`AU_yqL...`），**不含任何 http 地址** | **失效** |
| ② HEAD 跟随读 `Location` | 返回 **204，无 Location** | **失效** |
| ③ GET 解析页面找 `data-n-au` | 200，607 KB，**页面中不存在 `data-n-au`**，是 Angular SPA 壳 | **失效** |
| ④ Google `batchexecute` 接口 | 200，但返回 `["wrb.fr","Fbv4je",null,...[3]...]` 即空结果 | **失效** |

补充实测：短时间内连续请求该域名会返回 **429 Too Many Requests**。

**结论：当前无法通过程序拿到 Google News 条目的原始文章 URL。**

替代方案（按推荐顺序）：

1. **用 `<source url>` 的域名直接定级**，`article.original_url` 置空，`article.resolve_status='unresolved'`，保留 Google News 跳转链接供人工点开核对。人工审核本来就要看一眼原文，这个损失可以接受。
2. 用 `<title>` 剥离媒体名后，在 `<source url>` 域名站内搜索，尝试匹配真实 URL（实现成本高，命中率未知，列为后置）。
3. 若后续 Google 换接口，再补适配。

**受此影响，`article.source_level` 的优先级顺序要调整**：`<source url>` 域名定级优先于"回溯后定级"，回溯从"必需步骤"降级为"可选增强"。

## 4. 期望的规范化输出

### 4.1 `RawItemDraft` 字段期望

| 字段 | 取值来源 | 期望值 / 约束 | 允许空 |
|---|---|---|---|
| `source_id` | 配置 | 正整数 | 否 |
| `url` | `<link>` | 原始链接；Google News 为跳转链接 | 否 |
| `resolved_url` | 回溯 | 当前多数为 `null`，见 §3.5 | 是 |
| `title` | `<title>` | 已剥离媒体后缀与首尾空白 | 否 |
| `summary` | `<description>` | 纯文本，长度 200—600 字符（实测区间） | 是 |
| `published_at` | `<pubDate>` | UTC aware datetime | 是 |
| `published_raw` | `<pubDate>` 原文 | 原样保留，用于排障 | 是 |
| `author` | `dc:creator` / `author` | 可能为空串 | 是 |
| `extra` | 源特有 | 至少保留 `media_thumbnail`、`categories`、`publisher_name`、`publisher_url` | 是 |
| `fetched_at` | 抓取时刻 | UTC aware | 否 |

硬约束（可直接写成断言）：

1. `title` 不为空，且不等于 `"Google 新闻"`（实测 Google News 的 **channel 标题**会污染 item 列表）。
2. `url` 必须是 `http:` 或 `https:` 开头。
3. `published_at` 若存在，必须落在 `[2000-01-01, now + 1 天]`。
4. `summary` 不含未解码的 HTML 实体（`&lt;`、`&#8230;`、`&amp;nbsp;`）。

### 4.2 四条真实样本的期望输出

**NASA（类型 A）**

```json
{
  "source_id": 1,
  "url": "https://science.nasa.gov/image-article/apod-2026-november-25-spherex-seeing-through-dust/",
  "resolved_url": "https://science.nasa.gov/image-article/apod-2026-november-25-spherex-seeing-through-dust/",
  "title": "APOD: 2026 November 25 – SPHEREx Seeing Through Dust",
  "summary": "APOD Science APOD APOD: 2026 November 25 –… Today's APOD Archive …",
  "published_at": "2026-11-25T05:05:00+00:00",
  "published_raw": "Wed, 25 Nov 2026 05:05:00 +0000",
  "author": "",
  "extra": { "categories": ["APOD"], "has_content_encoded": true }
}
```

注意 `published_at` 期望带时区 `+00:00`，不是裸 datetime。

**phys.org（类型 B，guid 陷阱）**

```json
{
  "source_id": 5,
  "url": "https://phys.org/news/2026-11-south-pole-telescope-clearest-distant.html",
  "title": "South Pole Telescope releases clearest map ever of matter in the distant universe",
  "summary": "The earliest light in the universe, known as the cosmic microwave background (CMB) ...",
  "published_at": "2026-11-25T15:00:01+00:00",
  "published_raw": "Wed, 25 Nov 2026 10:00:01 EST",
  "extra": { "guid_raw": "news714821461", "categories": ["Astronomy"] }
}
```

`10:00:01 EST` 换成 UTC 是 `15:00:01`；若按 UTC−4 误算会得到 `14:00:01`，**差 1 小时**。这个差值应写进断言做回归保护。

**ScienceDaily（类型 C，编码陷阱）**

```json
{
  "source_id": 8,
  "url": "https://www.sciencedaily.com/releases/2026/11/261124055852.htm",
  "title": "A space telescope hunting for dark matter just discovered something unexpected",
  "summary": "ESA's Euclid space telescope has discovered its first previously unknown comet ...",
  "published_at": "2026-11-25T10:35:04+00:00",
  "published_raw": "Wed, 25 Nov 2026 05:35:04 EST",
  "extra": { "charset_detected": "utf-8", "charset_from_header": null }
}
```

关键断言：**`summary` 里的撇号必须是 U+2019（显示为 `ESA's`）**；若出现 `â€™`，说明解码用错了。这是编码环节最直接的回归判据。

**Google News（类型 D）**

```json
{
  "source_id": 13,
  "url": "https://news.google.com/rss/articles/CBMiZkFVX3lxTFBwa2Z...",
  "resolved_url": null,
  "title": "地球引力临时捕获一颗“迷你月球”",
  "summary": null,
  "published_at": "2026-11-25T07:00:34+00:00",
  "published_raw": "Wed, 25 Nov 2026 07:00:34 GMT",
  "extra": {
    "publisher_name": "科学网—新闻",
    "publisher_url": "https://news.sciencenet.cn",
    "resolve_status": "unresolved"
  }
}
```

关键断言：`title` 已去掉 ` - 科学网—新闻`；`extra.publisher_url` 已提取。

### 4.3 落库后的期望

| 表 | 期望 |
|---|---|
| `raw_item` | 每次成功拉取新增；`raw_html` 仅在 `content:encoded` 存在时非空 |
| `article` | `status='ingested'`；`source_level` 已定级；`source_level_reason` 非空 |
| `task_run` | `status='success'`；`stats_json` 含 `fetched/inserted/skipped_dup/skipped_old/not_modified` |
| `source` | `last_poll_at`、`last_success_at` 已更新；`etag` 已保存 |

`source_level_reason` 期望格式：`rule2:nasa.gov`、`rule4:phys.org`、`unresolved`。**每一项都必须能回答"为什么是这一级"。**

## 5. 采集相关接口的期望返回值

### 5.1 通用约定

- 前缀 `/api`；时间一律 ISO 8601 UTC，形如 `2026-11-25T05:05:00Z`。
- 分页参数 `page`（默认 1）、`page_size`（默认 20，上限 100）；返回 `items` / `total` / `page` / `page_size`。
- 错误格式：`{ "code": "...", "message": "...", "detail": ... }`。
- 除登录外，所有接口未带有效凭证返回 401。

### 5.2 `POST /api/sources/{id}/poll`

触发一次采集，**必须异步**，不能同步返回抓取结果。

请求：空 body 或 `{}`

成功 `202 Accepted`：

```json
{
  "task_run_id": 1024,
  "source_id": 1,
  "status": "pending",
  "message": "已排队，等待 worker 执行"
}
```

失败：

| 场景 | 状态码 | code |
|---|---|---|
| 源不存在 | 404 | `source_not_found` |
| 源已停用 | 409 | `source_disabled` |
| 同源已有 pending/running 任务 | 409 | `source_busy` |
| 未登录 | 401 | `unauthorized` |

### 5.3 `GET /api/task-runs`

查询参数：`source_id`、`status`、`from`、`to`、`page`、`page_size`

成功 `200`：

```json
{
  "items": [
    {
      "id": 1024,
```

## 6. 边界条件清单

编号规则：`前缀-序号`。优先级 `P0` 必测、`P1` 应测、`P2` 可后置。状态：`实测` 是本次已观察到的，`待测` 是推断。

### 6.1 网络与 HTTP（NET）

| 编号 | 场景 | 期望行为 | 状态 | 优先级 |
|---|---|---|---|---|
| NET-01 | 正常 200 | 解析入库，`task_run=success` | 实测 | P0 |
| NET-02 | 304 Not Modified | `not_modified=true`，不写 `raw_item`，计入 success | 待测 | P0 |
| NET-03 | 401 / 403 | 不重试，`health_status='auth_error'` | 实测（ATel 403） | P0 |
| NET-04 | 404 | 不重试，`consecutive_failures+1` | 实测（phys_neuro、sd_bci、tianapi） | P0 |
| NET-05 | 429 限流 | 读 `Retry-After` 后再退避，不立刻重试 | 实测（Google News 连续请求触发） | P0 |
| NET-06 | 5xx | 重试 3 次，指数退避 | 待测 | P0 |
| NET-07 | 连接被对端关闭 | 视为瞬时错误重试 | 实测（ESA） | P0 |
| NET-08 | 连接超时 / 读超时 | 5s 连接、10s 读超时后重试 | 实测（ESA 备用地址 25s） | P0 |
| NET-09 | DNS 解析失败 | 不重试（无意义），`connection_error` | 待测 | P1 |
| NET-10 | TLS 证书错误 | 不重试，记 `tls_error`，**不要静默跳过证书校验** | 待测 | P1 |
| NET-11 | 重定向超过 5 跳 | 中止，记 `too_many_redirects` | 待测 | P2 |
| NET-12 | 响应体超过 `MAX_RESPONSE_BYTES` | 截断并记 warning，不 OOM | 待测 | P1 |
| NET-13 | 响应 Content-Type 是 `text/html` | 判 `not_a_feed`，不当成空 feed | 实测（ESA 页面地址） | P0 |
| NET-14 | 响应是 gzip / br 压缩 | 正确解压后再解析（`httpx` 默认处理） | 待测 | P1 |
| NET-15 | 服务端返回空 body | 判 `empty_response`，不抛未捕获异常 | 待测 | P1 |

### 6.2 报文与解析（PARS）

| 编号 | 场景 | 期望行为 | 状态 | 优先级 |
|---|---|---|---|---|
| PARS-01 | 标准 RSS 2.0 | 正常解析 | 实测 | P0 |
| PARS-02 | Atom（`<entry>` 而非 `<item>`） | 正常解析，字段映射一致 | 待测 | P1 |
| PARS-03 | XML 语法错误（BozoError） | 判 `parse_error`，不崩溃，记原始报文前 2 KB | 待测 | P0 |
| PARS-04 | 合法 XML 但不是 feed（HTML 页面） | 判 `not_a_feed`，`items=0` | 实测 | P0 |
| PARS-05 | 合法 feed 但 0 条 | 判 `empty_feed`，`task_run=success`，**不计入失败** | 实测 | P0 |
| PARS-06 | channel 级 `<link>` 混入 | 只解析 `<item>` 内的 link，不抓 channel 的 | 实测（Google News 18 条 link 中 2 条是 channel 级） | P0 |
| PARS-07 | channel 标题被当成 item 标题 | 过滤掉等于 channel title 的条目 | 实测（"Google 新闻"） | P0 |
| PARS-08 | item 缺 `<title>` | 用 summary 首 50 字兜底，或丢弃并计数 | 待测 | P1 |
| PARS-09 | item 缺 `<link>` | 丢弃，记 `missing_link` | 待测 | P0 |
| PARS-10 | item 缺 `<pubDate>` | 入库，`published_at=null`，下游归待定 | 待测 | P0 |
| PARS-11 | `dc:creator` 为空 CDATA `<![CDATA[]]>` | 解析成空串，不报错 | 实测（NASA） | P0 |
| PARS-12 | description 含 HTML 标签 | 清洗为纯文本 | 实测（FNAL、watchers） | P0 |
| PARS-13 | description 含转义 HTML（`&lt;a href`） | 先反转义再清洗 | 实测（Google News） | P0 |
| PARS-14 | description 以 `[&#8230;]` 截断 | 去掉截断标记 | 实测（NASA） | P1 |
| PARS-15 | `content:encoded` 存在且很大 | 存入 `raw_html`，但**摘要字段只取 description** | 实测（NASA 23 KB/条） | P0 |
| PARS-16 | `<guid>` 不是 URL | 只用 `<link>` 作 URL，`guid` 仅存入 `extra` | 实测（phys.org `news714821461`） | P0 |
| PARS-17 | 多个 `<category>` | 全部收集进 `extra.categories` | 实测（FNAL 2 个） | P1 |
| PARS-18 | 带 `<media:thumbnail>` / `<enclosure>` | 存入 `extra`，MVP 不下载图片 | 实测（phys.org） | P2 |
| PARS-19 | CDATA 内含 `]]>` 转义 | 正确还原 | 待测 | P2 |
| PARS-20 | 同一 feed 内重复条目 | 入口去重拦掉，计 `skipped_dup` | 待测 | P0 |
| PARS-21 | 标题含全角/半角混合、多余空格 | 归一化后入库 | 待测 | P1 |

### 6.3 时间与时区（TIME）

| 编号 | 场景 | 期望行为 | 状态 | 优先级 |
|---|---|---|---|---|
| TIME-01 | RFC822 带 `+0000` | 转 UTC | 实测（NASA、FNAL、watchers） | P0 |
| TIME-02 | RFC822 带 `GMT` | 转 UTC | 实测（Google News） | P0 |
| TIME-03 | RFC822 带 `EST` | 按 UTC−5 解释（不是 EDT 的 −4） | 实测（phys.org、ScienceDaily） | P0 |
| TIME-04 | RFC822 带 `PDT` / `CEST` 等 | 按对应时区缩写解析 | 待测 | P1 |
| TIME-05 | ISO 8601 带 `Z` / `+08:00` | 转 UTC | 待测 | P0 |
| TIME-06 | 无时区（`2026-11-25 10:00:00`） | 按 UTC 处理，记 `tz_assumed='UTC'` | 待测 | P0 |
| TIME-07 | 只有日期无时间 | 补 `00:00:00`，记 `time_precision='date'` | 待测 | P1 |
| TIME-08 | 中文格式（`2026年11月25日`） | 优先按格式表解析，失败则 `time_parse_failed` | 待测 | P1 |
| TIME-09 | 无法解析的乱码时间 | `published_at=null`、`time_parse_failed=true`，不丢弃 | 待测 | P0 |
| TIME-10 | 未来时间（now + 3 天） | 保留但标 `future_time=true`，下游归待定 | 待测 | P1 |
| TIME-11 | 极老时间（2010 年） | 落地窗口拦掉，计 `skipped_old` | 待测 | P0 |
| TIME-12 | 1970-01-01（解析失败兜底值） | 视为非法，`published_at=null` | 待测 | P1 |
| TIME-13 | 夏令时切换日的时间 | 按带偏移量解析，不自行推断 | 待测 | P2 |

### 6.4 编码（ENC）

| 编号 | 场景 | 期望行为 | 状态 | 优先级 |
|---|---|---|---|---|
| ENC-01 | HTTP header 带 `charset=UTF-8` | 按 UTF-8 解码 | 实测（NASA、FNAL） | P0 |
| ENC-02 | HTTP header **不带** charset | 显式按 UTF-8 解码，失败再嗅探 | 实测（ScienceDaily 只给 `application/xml`） | P0 |
| ENC-03 | XML 声明 `encoding="GBK"` | 按声明解码 | 待测 | P1 |
| ENC-04 | header 与 XML 声明冲突 | 以能成功解码且无替换字符者为准，记 warning | 待测 | P1 |
| ENC-05 | 文件带 UTF-8 BOM | 剥掉 BOM，避免首个标签解析失败 | 待测 | P1 |
| ENC-06 | 非法 UTF-8 字节 | `errors='replace'` 并记 warning，不中断整批 | 待测 | P1 |
| ENC-07 | 中文源返回 GB2312 实际是 GBK | 用 `charset_normalizer` 猜测 | 待测 | P2 |

**ENC-02 的实质是"不要依赖服务器声明编码"**：ScienceDaily 是 60 条/次的大源，一旦解码策略选错，整批摘要都会带乱码，而且不会报错。

### 6.5 链接（LNK）

| 编号 | 场景 | 期望行为 | 状态 | 优先级 |
|---|---|---|---|---|
| LNK-01 | 普通直达 URL | `resolved_url = url` | 实测 | P0 |
| LNK-02 | Google News 跳转链 | `resolved_url=null`，`publisher_url` 从 `<source url>` 取 | 实测 | P0 |
| LNK-03 | 跳转链 HEAD 返回 204 无 Location | 不重试，直接判 unresolved | 实测 | P0 |
| LNK-04 | token base64 解码 | 不期望得到 URL，不实现该路径 | 实测 | P0 |
| LNK-05 | URL 带 `utm_*` / `spm` / `ref` | 归一化时剔除 | 待测 | P1 |
| LNK-06 | URL 带无关随机参数 | `url_hash` 应基于归一化 URL | 待测 | P1 |
| LNK-07 | 相对链接（`/news/123`） | 用 feed 的 host 补全 | 待测 | P1 |
| LNK-08 | 非 http(s) scheme（`ftp:`、`javascript:`） | 丢弃 | 待测 | P1 |
| LNK-09 | URL 超长（> 2000 字符） | 截断或丢弃并记 warning | 待测 | P2 |
| LNK-10 | 同一 URL 出现在不同源 | 第二次计入 `skipped_dup`，`source_id` 追加到 `dup_sources` | 待测 | P1 |
### 6.6 定级（GRADE）

| 编号 | 场景 | 期望行为 | 状态 | 优先级 |
|---|---|---|---|---|
| GRADE-01 | 域名命中 whitelist A | `A`，reason `rule2:<domain>` | 待测 | P0 |
| GRADE-02 | 域名命中 whitelist B | `B`，reason `rule3:<domain>` | 待测 | P0 |
| GRADE-03 | 域名命中 blocklist | `C`，reason `rule1:<domain>` | 待测 | P0 |
| GRADE-04 | **A 级源夹带外部链接** | 外部域名不在 `expected_domains` → 不升 A | 实测（FNAL feed 内 link 指向 `bhpioneer.com`） | P0 |
| GRADE-05 | 子域归一 | `news.bbc.co.uk` → `bbc.co.uk` | 待测 | P1 |
| GRADE-06 | 相似域名 | `notnasa.gov` **不得**命中 `nasa.gov` | 待测 | P0 |
| GRADE-07 | 大小写 / 端口 | `NASA.gov:443` → `nasa.gov` | 待测 | P1 |
| GRADE-08 | Google News 用 `<source url>` 定级 | 按媒体域名定级，不等回溯 | 实测可行 | P0 |
| GRADE-09 | `<source url>` 缺失 | 回退到 `unresolved` → C | 待测 | P1 |
| GRADE-10 | IP 直连 URL | 不在白名单 → C | 待测 | P2 |

GRADE-04 是本项目最容易被忽略的陷阱：**A 级源 ≠ A 级文章**。实测 Fermilab 的 feed 里第一条 `<link>` 指向 `bhpioneer.com`（地方媒体转载），如果不校验 `expected_domains`，这条会被误判成 A 级直推。

### 6.7 去重与幂等（DEDUP）

| 编号 | 场景 | 期望行为 | 状态 | 优先级 |
|---|---|---|---|---|
| DEDUP-01 | 同一源同一条目重复抓 | 第二次 `skipped_dup`，不新增 `article` | 待测 | P0 |
| DEDUP-02 | 跨源同 URL | 第二次 `skipped_dup`，`dup_sources` 追加 | 待测 | P1 |
| DEDUP-03 | 跨源同标题不同 URL | **不去重**（留给事件级） | 待测 | P1 |
| DEDUP-04 | 标题仅标点/空格不同 | `title_fingerprint` 相同 | 待测 | P1 |
| DEDUP-05 | URL 仅追踪参数不同 | 归一化后同 `url_hash` | 待测 | P1 |
| DEDUP-06 | 并发两次写入同 URL | 唯一索引拦掉，捕获 `IntegrityError` 不报 500 | 待测 | P0 |
| DEDUP-07 | 手工导入已存在的 URL | 返回 200 + `duplicate=true` | 待测 | P1 |
| DEDUP-08 | 同源 `feed` 内部重复条目 | 一次任务内去重 | 待测 | P1 |

### 6.8 调度与并发（SCHED）

| 编号 | 场景 | 期望行为 | 状态 | 优先级 |
|---|---|---|---|---|
| SCHED-01 | 同源任务未结束又被触发 | `max_instances=1` 或 `source_busy`，不并发 | 待测 | P0 |
| SCHED-02 | 手动触发与定时同时到 | 只跑一次，另一次跳过并留痕 | 待测 | P0 |
| SCHED-03 | Worker 崩溃后残留 `running` | 启动时标记 `failed`，`error='worker restarted'` | 待测 | P0 |
| SCHED-04 | 机器休眠错过定时 | `misfire_grace_time=300` 内补跑，超出则跳过 | 待测 | P1 |
| SCHED-05 | 系统时钟回拨 | 不产生负耗时的 `task_run` | 待测 | P2 |
| SCHED-06 | `pending` 任务长期无 Worker | Dashboard 可见积压，不静默消失 | 待测 | P1 |
| SCHED-07 | 一次任务处理 60 条 | 单源耗时可控（实测单次请求 0.5—3s） | 实测 | P1 |

### 6.9 数据量与存储（VOL）

| 编号 | 场景 | 期望行为 | 状态 | 优先级 |
|---|---|---|---|---|
| VOL-01 | 单条 `content:encoded` 23 KB | 存 `raw_html`；`RAW_HTML_MAX_DB_BYTES=1MB` 内 | 实测（NASA） | P0 |
| VOL-02 | 单源单次 60 条 | 正常入库，不超时 | 实测（ScienceDaily） | P0 |
| VOL-03 | 单源单次 226 KB | 正常解析 | 实测（NASA） | P0 |
| VOL-04 | 单条 description 600 字符 | 不截断（低于限制） | 实测（FNAL） | P1 |
| VOL-05 | 全源一天累计估算 | 见 §8 收敛项 | 待测 | P1 |
| VOL-06 | `raw_html` 超阈值 | 落 `storage/raw/`，库里存路径 | 待测 | P1 |

按实测数据粗算：18 源 × 平均 25 条 × 每天 24 次轮询（30 分钟一次）≈ 每天**首拉去重后**新增约 100—300 条。`raw_item` 一年约 3.6 万—11 万条，单机 PostgreSQL 完全无压力。

### 9.2 关键原始片段

**phys.org 的 guid 不是 URL**

```xml
<guid isPermaLink="false">news714821461</guid>
```

**ScienceDaily 不带 charset**（服务器原样，但字节是合法 UTF-8）

```
Content-Type: application/xml        ← 没有 charset
```

这是"缺声明"，**不是源的内容坏了**：原始字节按严格 UTF-8 解码完全成功，`Euclid` 那句里的撇号是正常的 U+2019。

**Google News 的 publisher 信息**

```xml
<source url="https://news.sciencenet.cn">科学网—新闻</source>
```

**Fermilab feed 夹带外部链接**（A 级源 ≠ A 级文章）

```xml
<link>https://www.bhpioneer.com/local_news/dune-activity-significantly-increasing-at-surf/article_70e2a468-....html</link>
```

**Google News 跳转页无解析线索**（607 KB 中不含 `data-n-au`，且 final URL 未变）

```
status=200 len=607581 final=https://news.google.com/rss/articles/CBMi...?oc=5&hl=zh-CN&gl=CN&ceid=CN:zh-Hans
data-n-au present: False
```
