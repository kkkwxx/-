## 0. 一句话与边界

**把"能点开的条目"变成"值得人看一眼的事件线索"：先用便宜规则砍掉明显垃圾，再用 AI 判"这是不是一件具体发生的事"，最后归入五类。**

边界很清楚：

| 本模块负责 | 不负责 |
|---|---|
| 标题清洗、硬排除、软扣分 | 原始数据落库（04） |
| `is_event` 判定（是事件 / 不是事件） | 事件真伪核实 |
| 五类归类 + `content_nature` | 事件级合并去重（06） |
| `review_priority` 排序分 | 时效门禁（06） |
| 排除词 / 信号词配置（`keyword_rule`） | 标题正文生成（08） |

**本模块不做"有损删除"。** 被判排除的条目改 `status='rule_rejected'` 并记 `reject_reason`，数据留在库里，随时可复查——和 04「先存后判」一脉相承。

## 1. 为什么先看 232 条真实标题再定词

（详见 [05-标题样本-2026-11-26.md](./05-标题样本-2026-11-26.md)）四个事实直接决定了本文的设计：

**① 等级不等于相关性。** `phys_neuro` 的 30 条全是社会科学：AI 与数学、媒体自由、爱尔兰鹿骨、新石器时代发酵奶、伴侣体味与亲密关系、黑五购物心理、全球葡萄酒危机……**与「脑机/意识」相关 0 条**。而 `phys.org` 在域名规则表里是 A，所以这些文章**文章级仍是 A**。源级降 B 只影响分组与统计，不影响定级。

→ 结论：**相关性必须由 `is_event` 判，不能靠等级兜底。**

**② 最大噪音不是财经，是行业动态。** 需求文档列的是教程/广告/星座/影视，实采里几乎打不到靶；真正占大头的是产业新闻：

| 模式 | 命中 | 分布 | 典型 |
|---|---|---|---|
| 行业会议 | 13 | A1 / C12 | 2026脑机接口大会举办 · 工信部脑机接口标委会工作组成立 · 昌平产业园获评「中关村特色产业园」 |
| 政策动态 | 9 | C9 | 政策加码+技术突破+资本涌入 多重因素赋能脑机接口产业发展 |
| 投资机构 | 6 | C6 | 多只概念股获机构扎堆调研(附股) |
| 游戏 | 13 | C13 | 《魔兽世界》副本门钥匙任务大盘点 · 《Quack Hunters》试玩版公开 |
| 财经代码/涨跌 | 3 | C3 | 完美世界(002624.SZ)：上半年净亏损1.18亿元 |

**③ 单字词会误杀。** 三个真实例子：

| 若当硬排除 | 会误杀 |
|---|---|
| `如何` | 光明网《科技观察｜脑机接口走向临床，如何证明"非它不可"？》 |
| `《》` | Jiemian《四肢瘫痪受试者植入脑机接口玩转 GTA6》——BCI 里程碑事件 |
| `大会` | 新华网《2026腾冲科学家论坛将首次举办脑机接口等特色专题活动》（A 级源） |

→ 结论：**弱特征只能软扣分，且必须配"白名单救回"；硬排除只放强特征。**

**④ 标题尾巴是媒体名。** `- Sohu` / `- 36Kr` / `- 网易新闻客户端` / `- 科学网—新闻` / `- 财联社电报`。GN 的 `publisher_name` 已单独存了 → 这批属于**清洗**，不属于排除。

## 2. 处理链路

```
article(status='ingested')
   │
   ├─ L1 清洗        标题去媒体尾巴 / GN 后缀 / 空白归一   → article.title
   │
   ├─ L2 硬排除      命中 exclude_hard 任一条             → status='rule_rejected'，结束
   │
   ├─ L3 软扣分      命中 exclude_soft → priority -N      → 继续（不拒绝）
   │
   ├─ L4 is_event    规则预判 + AI 结构化判定
   │      ├─ is_event=false  → status='rule_rejected'，reject_reason='not_event:<category>'
   │      ├─ 判不准/低置信  → status='pending'
   │      └─ is_event=true   → L5
   │
   ├─ L5 五类归类    命中/未命中 → event_type + 置信度
   │      ├─ 明确命中    → event_type 写入
   │      └─ 归不进去    → event_type=NULL，仍可进 pending
   │
   └─ L6 排序        review_priority = 等级分 + 信号词分 − 软扣分 → status='candidate' 或 'pending'
```

**顺序不能换**：先清洗再匹配（否则媒体尾巴会干扰 `- Sohu` 这类后缀匹配）；先硬排除再调 AI（省钱，实测能去掉约 45—50 条 / 137 条 C 级）；先 `is_event` 再归类（不是事件的东西归类没有意义）。

**`status` 三态落点**（与 01-总体架构 §3 状态机一致）：

| 结果 | `status` | 写什么 |
|---|---|---|
| 硬排除 | `rule_rejected` | `reject_reason = 'rule:<group>:<word>'` |
| 非事件 | `rule_rejected` | `reject_reason = 'not_event:<category>'` |
| 事件 + A/B 级 + 置信度高 | `candidate` | `event_type`、`review_priority` |
| 事件但 C 级 / 灵异边界 / 低置信 / 归类不确定 | `pending` | 同上 + `review_priority` 偏低 |

**C 不是丢弃，是进待定池**（03 §6.3 fail-safe 的延续）。

## 3. `keyword_rule` 表

复用 01-总体架构 §6 已声明的 `keyword_rule` 实体，不新加表。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | int PK | |
| `type` | enum | `exclude_hard` / `exclude_soft` / `anchor` / `signal` / `event_verb` |
| `category` | str | 见 §3.2，报表按它聚合 |
| `pattern` | text | **正则**（`re.search`，大小写不敏感）；纯词也写成正则字面量 |
| `weight` | int | `signal` 加分、`exclude_soft` 扣分；其余类型此值忽略 |
| `scope` | enum | `title`（默认）/ `title_summary` / `all`（含正文）。**排除词一律 `title_summary`**，不扫正文，避免正文里的引用误伤 |
| `enabled` | bool | 软删除 |
| `note` | text | 为什么有这条词，附实采例句 |
| `created_at` / `updated_at` | datetime | |

**为什么用正则而不是纯词表**：股票代码 `\(\d{6}\.(SZ|SH|HK)\)`、媒体尾巴 `\s*[-–|]\s*(Sohu|36Kr|…)$` 这类靠字面词穷举不出来。但正则允许写坏（如 `.` 未转义），所以配置走 seed + 单测校验（§10），不在 UI 里自由编辑。

### 3.2 `category` 取值

`finance`（财经股票）/ `game`（游戏）/ `entertain`（影视小说综艺）/ `divination`（星座命理）/ `industry`（行业动态）/ `policy`（政策规划）/ `recruit`（招聘招生）/ `announce`（活动预告）/ `signal`（泛宇宙信号词）/ `anchor`（栏目锚定词）/ `verb`（事件动词）

## 4. 排除词表 v0

> 全部词条带实采命中数，跑 `python -m app.seed` 灌入。加词优先、删词谨慎（04 §5.3 同一条纪律）。

### 4.1 硬排除（命中即 `rule_rejected`）

只放**强特征**：命中它基本可以断定"这不是我们要的新闻"。

| category | 正则（片段） | 实采命中 | 说明 |
|---|---|---|---|
| `finance` | `\(\d{6}\.(SZ\|SH\|HK)\)`、`概念股`、`涨停`、`跌停`、`净亏`、`净利`、`营收`、`市值`、`机构调研`、`北向资金`、`减持`、`增持`、`招股`、`业绩预告` | 10 | 股票代码是最硬的信号 |
| `game` | `副本`、`攻略`、`赛季`、`试玩`、`开服`、`抽卡`、`皮肤`、`版本更新`、`手游`、`端游` | 13 | 注意**不要**加 `游戏` 单字：`意念玩《GTA 6》` 是 BCI 事件，靠 `game` 组其它词兜 |
| `entertain` | `电影`、`电视剧`、`预告片`、`上映`、`票房`、`番剧`、`短剧`、`综艺` | 0 | 本批未命中，仍保留（需求明确要求） |
| `divination` | `星座`、`运势`、`财运`、`桃花`、`今日运程`、`算命`、`风水`、`开光`、`转运`、`免费测算` | 0 | 同上 |

**硬排除 4 组共 23 条实测命中**（去重前），占 232 条的 10%。

### 4.2 软扣分（不拒绝，只降 `review_priority`）

弱特征：单独出现很可疑，但可能是真事件的背景。

| category | 正则（片段） | weight | 实采命中 | 为什么软 |
|---|---|---|---|---|
| `industry` | `大会`、`论坛`、`峰会`、`研讨会`、`沙龙`、`博览会`、`标委会`、`工作组`、`联盟`、`产业园`、`创新中心`、`产业对接`、`活动预告`、`发布会` | −3 | 13 | 「科技大会宣布重大发现」是真事件；新华网那条 A 级源也被命中 |
| `policy` | `政策`、`规划`、`指导意见`、`试点`、`部委`、`工信部`、`科技部`、`省级`、`市级` | −2 | 9 | 「NASA 启动试点任务」是事件 |
| `recruit` | `招聘`、`招生`、`考试`、`报名`、`岗位`、`宣讲会` | −5 | 0 | 基本可以确定无关，但保留软性以防万一 |

**软扣分不写 `reject_reason`**，只在 `review_priority` 上体现，审核台按优先级排序时自然沉底。

### 4.3 组合规则与白名单救回（关键）

```
硬排除生效 = 命中 exclude_hard 任一
软扣分     = Σ 命中 exclude_soft 的 weight（取最负的一条，不累加，避免一条标题被打成 -9）

白名单救回 = 命中 ≥1 个 anchor（栏目锚定词） 且 命中 ≥1 个 event_verb
            → 忽略该条**全部软扣分**（硬排除不受影响）
```

**为什么不累加软扣分**：一条标题同时含「大会」和「政策」就被打到 −5，与「招聘广告」同档，排序失去意义。取最负值即可。

**白名单只救软扣分，不救硬排除**：标题里有股票代码又提到「意念控制」，也是财经稿。

### 4.4 清洗规则（不是排除）

按顺序执行，结果写 `article.title`（`raw_title` 永远保留原样，审核台要对照）：

| # | 规则 | 例 |
|---|---|---|
| 1 | 去尾部媒体名：`\s*[-–—|]\s*<媒体名>\s*$`（媒体名来自本月观察到的集合 + `raw_item.publisher_name`） | `…玩转GTA6 - Jiemian.com` → `…玩转GTA6` |
| 2 | 去 GN 尾巴：`-\s*[^-]{1,20}$`（仅当尾巴与 `publisher_name` 相同或高度相似） | `…暗物质新进展 - 新华社` → 去掉 |
| 3 | 去站点噪声后缀：`_今日要闻`、`- 网易新闻客户端`、`【无限服】` | |
| 4 | HTML 实体与标签（04 §8.2 已做，这里兜底） | `&nbsp;` |
| 5 | 空白归一 + NFKC | |

**第 1、2 条要写成"媒体名白名单 + 相似度校验"**，不能简单截断：`…下半年净亏损1.18亿元 - TradingView` 后面那段是真的数字，截错就丢信息。

## 6. `is_event` 判定

### 6.1 什么算"事件"

**事件 = 主体 + 动作 + 时间/地点线索 + 可核验**。四缺一就不是事件，或只能进待定。

| 是事件 | 不是事件 |
|---|---|
| 《Webb 首次在系外行星大气中探测到水汽》 | 《暗物质是什么？一文读懂》（科普） |
| 《浙大团队用脑机接口治疗难治性抑郁症取得突破》 | 《2026 脑机接口大会举办》（行业动态） |
| 《NASA 的 DART 撞击使小行星轨道改变》 | 《十大最神秘 UFO 事件盘点》（榜单） |
| 《患者植入脑机接口后用意念玩 GTA6》 | 《政策加码+资本涌入 赋能脑机接口产业》（评论） |

**明确排除的"非事件"子类**（写进 `reject_reason`）：`not_event:explainer`（科普解读）、`not_event:listicle`（榜单盘点）、`not_event:industry`（行业动态/会议）、`not_event:opinion`（评论观点）、`not_event:promo`（活动预告/招生招聘）、`not_event:image`（纯图片说明，如 APOD 每日图）。

> **APOD 这条来自实采**：NASA feed 里 `Eye of the Sahara`、`Georgia's Pecan Belt`、`APOD: 2026 November 25 – SPHEREx…` 都是每日一图，只有图没有事件。这类靠 AI 判 `not_event:image`，不靠排除词（标题里没有稳定特征）。

### 6.2 两段式：规则预判 + AI 结构化

**规则预判不改 `status`，只决定"怎么问 AI"**：

| 规则预判结果 | 条件 | 用途 |
|---|---|---|
| `likely_event` | 命中 anchor + event_verb，且无软扣分 | 送 `qwen3.8-flash`，prompt 带 hint |
| `uncertain` | 其它 | 同上，prompt 不带 hint |
| `likely_not_event` | 命中 `not_event` 类软扣分 ≥2 组，或标题长度 < 8 字 | prompt 明确要求"先判断是不是事件" |

**为什么不直接按规则拒**：实采证据在那儿——「大会」能命中 A 级源的正经预告，「如何」能命中光明网的深度报道。规则只做排序与提示，不做终判。

### 6.3 AI 调用规范

对齐 `AI编码对照.md` §2.5：

| 项 | 规定 |
|---|---|
| 模型 | `LLM_MODEL_CLASSIFY` = `qwen3.8-flash`，`enable_thinking=false` |
| 结构化 | **必须显式传** `response_format={"type":"json_object"}`；否则默认文本模式返回 json 围栏，`json.loads` 直接崩（实测） |
| 兜底 | 仍保留围栏剥离；再过 Pydantic；失败重试 1 次；再失败 → `status='pending'`，`is_event=NULL` |
| 输入 | `title` + `summary`（截断 800 字）+ `publisher_name` + `source_level`；**不传正文**（`blocked`/`thin` 占 61%，传了会造成输入不一致） |
| 缓存 | `ai_run.input_hash = sha256(model + prompt_version + title + summary)`，命中直接复用 |
| 预算 | 每日 `LLM_DAILY_TOKEN_BUDGET`；超限只做规则预判，其余留 `pending` |

### 6.4 输出 schema

    {
      "is_event": true,
      "event_type": "bci_consciousness",
      "category": "clinical_breakthrough",
      "event_time": "2026-11-25",
      "entities": ["浙江大学", "脑机接口", "难治性抑郁症"],
      "action": "临床试验取得突破",
      "content_nature": "科研进展",
      "confidence": 0.86,
      "reason": "有主体（浙大团队）、动作（临床突破）、时间（本月），可核验"
    }

`content_nature` 六种取值（**异常/灵能类必填，其它类可空**）：

| 值 | 含义 | 处置 |
|---|---|---|
| `科学事实` | 有同行评议或官方发布 | 常规 |
| `科研进展` | 论文/机构发布，尚未定论 | 常规 |
| `未证实目击` | 目击报告、单一信源 | 强制 `pending` |
| `灵异传闻` | 灵异/超自然叙述 | 强制 `pending` + 免责声明 |
| `娱乐化灵异` | 娱乐号/综艺/段子手包装的灵异内容 | 强制 `pending` + 免责声明（见 §7.3） |
| `伪科学主张` | 有明确科学主张但无依据 | 强制 `pending` + 风险标记 |

### 6.5 判定落点

| 条件 | `is_event` | `status` |
|---|---|---|
| `is_event=true` 且 `confidence ≥ 0.7` 且 `source_level ∈ {A,B}` 且 `content_nature ∈ {科学事实, 科研进展}` | true | `candidate` |
| `is_event=true` 但 `source_level='C'` | true | `pending` |
| `is_event=true` 但 `content_nature` 属灵异四类 | true | `pending` + `risk_flags=['supernatural']` |
| `is_event=true` 但 `confidence < 0.7` | true | `pending` |
| `is_event=false` 且 `confidence ≥ 0.8` | false | `rule_rejected`，`not_event:<category>` |
| `is_event=false` 但 `confidence < 0.8`，或 AI 失败 | NULL | `pending`（**判不准不丢**） |

| `neo` | 近地天体 | 小行星/彗星自身的发现、飞掠、撞击、采样 | 小行星、近地天体、飞掠、撞击、采样返回、asteroid、NEO、flyby、DART |
| `exoplanet` | 新星球 / 类地行星 | 系外行星的发现与大气/宜居性观测 | 系外行星、类地行星、宜居带、超级地球、exoplanet、habitable zone |
| `bci_consciousness` | 脑机 / 意识 | 脑机接口、神经解码、意识研究 | 脑机接口、意念控制、脑电、神经解码、意识、BCI、Neuralink |
| `anomaly_psychic` | 异常 / 灵能 | UFO/UAP、灵异、超自然现象 | UFO、UAP、不明飞行物、灵异、通灵、超自然、paranormal |

**一个事件可以跨类**（如「DART 撞击小行星后 Hera 拍到陨坑」既是 `neo` 又是深空）→ 取**主语所属**类别：主语是小行星 → `neo`；主语是探测器/望远镜 → `deep_space_particle`。

### 7.2 三条边界规则

**① 产业新闻 vs 临床突破（`bci_consciousness`）**

| 标题 | 归类 |
|---|---|
| 浙大团队用脑机接口精准治疗难治性抑郁症（患者结果） | `bci_consciousness`，是事件 |
| 工信部脑机接口标委会工作组成立 | 不是事件（`not_event:industry`） |
| 昌平脑科学与脑机接口产业园获评「中关村特色产业园」 | 不是事件（`not_event:industry`） |

判据：**有没有"患者/受试者/实验/观测"这类结果主体**。只有机构、园区、会议、政策 → 行业动态。

**② UFO vs 天文（`anomaly_psychic` vs `neo`）**

| 标题 | 归类 |
|---|---|
| 台湾惊现水母型 UFO？公路上空飘神秘黑烟圈 | `anomaly_psychic`（未证实目击） |
| Hera 探测器拍到 DART 撞击留下的陨石坑 | `neo` |

判据：**有没有可核验的天文/航天主体**。

**③ 灵异娱乐（`content_nature='娱乐化灵异'`，不排除）**

实采样例：

| 标题 | 处置 |
|---|---|
| 博士和硕士之间选择了道士，小小年纪就觉醒了天赋！（网易） | `anomaly_psychic` + `娱乐化灵异` + `pending` |
| 蜥蜴人靠这招伪装！为何最怕镜头？（禁闻网） | `anomaly_psychic` + `灵异传闻` + `pending` |
| 打造升空 UFO 造型法座 泰佛寺出奇招弘法 | `anomaly_psychic` + `娱乐化灵异` + `pending` |

**决策（已确认）**：这类**不排除**。理由：第五类内容本来就稀缺，"灵异报道"与"娱乐化灵异"边界模糊，排除会误杀真正的异常报道；交给人工在待定池判。但必须：

- 强制 `status='pending'`（不进 `candidate`）
- `content_nature` 必填
- 发布时强制带免责声明（`published_article.disclaimer`）
- `risk_flags` 追加 `supernatural`

**④ 排不进的怎么办**：`event_type=NULL`，只要 `is_event=true` 仍进 `pending`，审核台显示「待归类」。

## 8. 信号词与 `review_priority`

**泛宇宙信号词只加分，不作查询条件**（04 §5.2 已定，这里落地）：

    review_priority = 等级分 + 信号词分 + 锚定词分 − 软扣分 − 灵异惩罚

    等级分   = A:+30  B:+15  C:0
    锚定词分 = 命中的 anchor 类别数 × 5（上限 10）
    信号词分 = Σ signal.weight（每词 +2，命中 3 个以上按 6 封顶）
    软扣分   = min(exclude_soft.weight)（不累加，见 §4.3）
    灵异惩罚 = content_nature 属灵异四类 → −10

分档（审核台默认排序）：**≥40 高** / 25—39 中 / <25 低。`review_priority` 只影响排序与高亮，**不影响是否进候选**（01 §7 第 1 条）。

## 10. 评测与单测

### 10.1 评测集

`fixtures/eval/labeled.jsonl`，30—50 条，**从这份 232 条实采里挑**：

    {"title": "...", "summary": "...", "expect_status": "rule_rejected|candidate|pending",
     "expect_event_type": "neo|null", "expect_reject_reason_prefix": "rule:game|not_event:industry|null"}

挑选原则：4 类硬排除各 2—3 条、行业动态 5 条、灵异娱乐 4 条、A 级正样本 10 条、边界案例 5 条（GTA6 脑机、腾冲论坛预告、光明网深度、APOD 图片、DART 撞击）。

### 10.2 指标与门槛

| 指标 | 门槛 | 口径 |
|---|---|---|
| 硬排除误杀率 | **必须 0** | 标注为 `candidate` 的条目被 `rule:` 拒绝的比例 |
| `not_event` 精确率 | ≥ 0.85 | 判非事件的条目里真为非事件的比例 |
| 五类归类准确率 | ≥ 0.85 | 标注了 `event_type` 的条目 |
| 判不准兜底 | 100% | AI 失败必须落 `pending`，不能丢 |

### 10.3 单测（不调真实 LLM）

- 每条 `exclude_hard` 正则**至少一个实采例句**命中，且**不命中**同源 A/B 级正样本
- 三个已知误杀案例（`如何` / `《》` / `大会`）断言**不被硬排除**，`大会` 只软扣分
- 白名单救回：`anchor + event_verb` 的标题，软扣分为 0
- 清洗：媒体尾巴去除；`…净亏损1.18亿元 - TradingView` 的数字不被截断
- `is_event` 用 `respx` mock 百炼响应，覆盖：正常 JSON、围栏包裹、非法 JSON、超时、`is_event=false` 低置信
- 灵异四类必须落 `pending` + `risk_flags`
